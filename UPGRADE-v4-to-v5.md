# Обновление контура с v4 на v5

> Собрано ИЗ СЛЕДОВ исполнения (28.08.2026, план «Один пул на весь контур»), не по памяти:
> каждый шаг ниже был прогнан на копии живой базы v4 (33 МБ · 25 шагов журнала · 9 ролей),
> затем на живой, затем рождением с нуля. Числа — из тех прогонов.

## 1. Что появляется в v5 — и почему это один замысел, а не россыпь

**Смысл имени: один пул на весь контур — роли, которые не забывают.**

- **Пулы (треки) — живые.** У пула есть словесный план, слово владельца об открытии,
  скиллы под задачу (`tracks.skills`), а закрытие собирает **вердикты участников**
  (`track_verdicts`: документация · процесс) и отказывает поимённо, пока их нет.
  Инструмент `track.py`: open · plan · view · verdict · close · triage.
- **Статус роли пишется ТЕМ ЖЕ вызовом.** Закрытие карточки, взятие в работу и отправка
  записки обновляют `role_status` сами — отдельная кнопка статуса умерла нулём вызовов,
  вложенная прижилась (замер: поле молчало 22 дня и ожило первым же закрытием).
- **Карточки пула первыми.** Список и обзор пробуждения ставят карточки активного пула
  в голову; просроченное объявление работы («кто где») печатается каждым чтением —
  предикат вычисляется, не хранится. Шаг карточки пула — 60 минут, длиннее 90 — «раздели».
- **Память с историей и порогом.** `phoenix_history` хранит версии тел; сжатие раздела
  (`--allow-shrink`) ничего не теряет. Общий прогон судит **отставание** раздела от работы
  роли и **объём** (порог 20 000 знаков на раздел — красное поимённо).
- **Умения ролей протухают полем.** `role_skill.expired_at/expired_why`; паёк новой сессии
  (`role-brief.py`) протухшее умение не несёт — напоминание о протухшем вреднее отсутствия.
- **Аренды инструментов** (`tool_leases`): правка общего инструмента объявляется до правки,
  гаснет сама; читающему — предупреждение, пишущему — отказ.
- **Канал проблем процесса** — вердикты «process» закрытия пула → issues публичного
  образца (`gordi-issue.py`, писатель один — координатор; ворота трёх разделов:
  ЗАМЕР · КЛАСС · ПРЕДЛОЖЕНИЕ; пути обезличиваются).

### Чего в v5 нет намеренно
- **Демона напоминаний нет.** Просрочка и долги печатаются при каждом чтении — вычисляемое
  переживает перезапуски, хранимое умирает с сессией (оплачено нулём вызовов у четырёх
  хранимых механизмов).
- **Оценщики закрытия не назначаются.** Участие и есть назначение: состав собирается
  замером по карточкам и событиям пула.
- **Приоритет ноты остаётся полем и нормой** — производная срочность живёт в читалках.

## 2. Перед началом — одно обязательное условие

Бэкап, проверенный **разворачиванием**, а не свежестью дампа: снимите копию через
SQLite backup API (файловая копия при живых писателях в WAL-режиме даёт рваный снимок)
и откройте её запросом `SELECT * FROM schema_version` — она обязана ответить `v4`.

## 3. Как обновиться

Схемная половина **самозаписывается** (журнал шагов с отпечатком и автором — автор
берётся из окружения `MEZO_ROLE`, впечатанное имя журнал отвергает приёмкой):

```
python <КОНТУР>/.mezosync/scripts/migrations/20260816-tool-leases.py --dry-run
python <КОНТУР>/.mezosync/scripts/migrations/20260816-tool-leases.py
… тот же порядок для: 20260820-role-skills · 20260822-sync-backoff-bridge-mtime ·
  20260823-phoenix-history · 20260827-track-verdicts-and-skills ·
  20260828-role-skill-expiry · 20260828-milestone-v5 (рубеж — ПОСЛЕДНИМ)
```

Каждый шаг идемпотентен: обрыв посередине лечится повторным прогоном (проверено —
повтор отвечает «уже объявлена, делать нечего», не вторым шагом в журнале).

Несхемная часть: инструменты кладутся в контейнер целиком (они выводят пути через
`mezo_paths`, впечатанных путей нет — гард образца держит ноль), правило
`shared-text-edit-sequence` в свод, навык `atlas-shared-edit` пересобирается генератором
из свода (`rules-to-skills.py --write`), витрина пулов — `GET /api/pool` Перископа.

### Защита, встроенная из чужого промаха
Рубеж отказывается объявляться, когда сверх прежней отметки ноль шагов: «рубеж без
шагов — украшение». А строитель пары не переносит файл, чья разница с шаблоном —
только заглушка пути: перенос затёр бы её путями одной машины.

## 4. Что произойдёт с вашими данными — и чего от этого ждать

Данные не трогаются: рубеж — запись-веха, новые сосуды рождаются пустыми. Счётчики
нот, карточек и памяти до/после равны (проверено на копии с 4052 нотами).

### Три вещи, которые вас удивят, и это не поломки
1. **Общий прогон покраснеет сразу** — новые проверки памяти включаются с живым долгом
   (в нашем контуре: 10 раздутых разделов и 2 отставших). Это намеренно: долг видим,
   руки свои у каждой роли, путь сжатия печатается в красном.
2. **Заведение карточки без пула предупреждает** («новое — только в пул») — при живом
   активном пуле это ворота, не запрет.
3. **Сон участниц живого пула прижат к 15 минутам** — потолок вернётся, когда объявления
   пула погаснут.

## 5. Как проверить, что получилось — по базе, а не по отчёту

```
SELECT * FROM schema_version;                        -- v5 · N · 0 (сверх рубежа НОЛЬ)
SELECT COUNT(*) FROM track_verdicts;                 -- сосуд существует (0 — норма)
SELECT COUNT(*) FROM phoenix_history;                -- версии памяти пишутся сжатием
python <КОНТУР>/.mezosync/scripts/guard-all.py       -- общий прогон; красное читайте
                                                     -- поимённо: часть — ваш живой долг
python <КОНТУР>/vnext-tools/bite-all.py              -- все приёмки разом (наш итог дня:
                                                     -- держится 79 · сломано 4 · не проверено 1,
                                                     -- и все красные были разобраны в тот же день)
```

## 6. Номер версии — почему он вычисляется

`schema_version` — витрина над журналом шагов: версия = последняя веха, «сверх рубежа» =
шаги после неё. Схема в этом каталоге **генерируется** (`vnext/tools/gen-schema.py`)
из живой базы; сверх рубежа не ноль — генератор кричит об этом в шапке файла.

## 7. Откат

Рубеж — одна строка журнала; откат = восстановление из бэкапа шага 2 (проверенного
разворачиванием). Точечно удалять строку вехи не надо: журнал append-only по духу,
и «схему меняли мимо журнала» — красное его собственной проверки.

## 8. Чем это проверено

- **Переходом на копии**: живая v4 (25 шагов · 7 сверх рубежа) → v5 · 0; отпечаток шага
  на копии и на живой СОВПАЛ (`c6d8e549d503dd65`) — переход детерминирован.
- **Повторным прогоном**: «уже объявлена — делать нечего», журнал не растёт.
- **Рождением с нуля**: `init-group` из этого образца в чистом каталоге →
  `schema_version = (v5, 0, 0)`, 45 инструментов, проба запуском отвечает.
- **Полным прогоном приёмок** в день рубежа и картой «поверхность → проверка»
  (`map-surface-guards.py`): пустые клетки видимы, подсадки объявлены контрактом PLANTS.
