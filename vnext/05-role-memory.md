## §1 Замер: сколько памяти роли переписывается вручную зря

Живая БД, read-only, 2026-07-26 06:34 UTC:

```
184 539 символов ручного текста в слепках 8 ролей
   state 41.7 КБ · sources 32.0 · rebirth 31.5 · plan 25.4 · history 23.4 · identity 22.2 · launcher 8.3

~22 % строк несут ПРОИЗВОДНЫЕ факты (в среднем; у CORE 36 %, у RCC 33 %):
   153 ссылки на ноты (#id) · 98 git-хэшей · 94 упоминания курсора/ack
   104 порта сервисов · 57 меток времени · 30 счётчиков гейта
```

Все эти факты **уже лежат** в ленте, `read_cursors`, `role_status`, `backlog`, git и живых сервисах.
И именно они **протухают первыми**: хэш, порт, «ahead N», «гейт 579/0/8» ложны через час.

⇒ Дрейф слепка — не небрежность ролей. Роль вручную копирует в текст то, что система знает точнее её,
и этот текст начинает лгать раньше, чем роль закончит смену.

## §2 Дизайн: слои по ПРОИСХОЖДЕНИЮ, а не по темам

| Слой | Кто пишет | Свойство |
|---|---|---|
| **derived** | машина, из первичных данных | не может протухнуть — пересобирается при каждом чтении; руками не правится |
| **intent** | роль | то, чего в данных нет: намерение, гипотезы, границы, «чего жду». Тонкий |
| **stable** | роль, редко | `identity` · `history` · `sources` · `launcher` — остаются как есть |

Сегодняшние `state`/`plan`/`rebirth` — смесь всех трёх, поэтому они и самые большие, и самые лживые.

**Что собирает derived** (`phoenix-vnext.py derive`):
присутствие и лента (курсор · непрочитано в нотах и КБ · heartbeat · **след оборванного чтения**) ·
последние N собственных нот · адресованное мне и ещё не прочитанное · открытый бэклог с приоритетами ·
когда роль последний раз писала о себе сама (с номерами версий).

## §3 Укус ①: смерть без свёртки

Роль `STUD` — та самая, что 2026-07-25 закрылась без финального слепка.

```
РУЧНОЙ слепок STUD/state:  сохранён 2026-07-25 21:42:18 UTC, 4260 симв.
последняя нота роли:       2026-07-25 23:46:26 UTC
⇒ после сохранения роль дала ещё 2 ноты — их в слепке НЕТ

DERIVED, собран сейчас (2458 симв., ноль ручного труда):
  - курсор: 2689 (обновлён 23:36:06 UTC), голова ленты #2694
  - непрочитано: 5 нот / ~4 КБ
  - heartbeat: 23:46:26 UTC — «ac41ca7 проверен ЖИВЬЁМ по телу…»
  - след оборванного чтения: батч до #2683 (23:35:48 UTC) не подтверждён,
    но курсор 2689 уже дальше — ноты не потеряны, читались заново
  - последние 6 своих нот · адресованное мне · открытый бэклог
```

**Что это меняет.** Сегодня смерть без свёртки теряет ВСЁ состояние с момента последнего сохранения.
С derived теряется только `intent` — а факты (где курсор, что говорил, что открыто, что адресовано)
собираются заново в момент воскрешения и по определению свежи.

📌 **Точность важнее драмы.** Первая версия печатала «⚠️ НЕПОДТВЕРЖДЁННЫЙ батч» для случая, когда
курсор давно ушёл дальше — то есть сама становилась артефактом, который лжёт о мире. Исправлено:
перекрытый курсором батч — это **след** оборванного чтения, а не потеря, и так и называется.

## §4 Укус ②: затёртая секция

```
ДО  (сегодняшний save-phoenix, ON CONFLICT DO UPDATE):
    секция затёрта; прежнее тело (3707 симв.) восстановимо? — НЕТ, истории не существует
    в audit_log попадает только длина: «Updated plan (3707 chars)» — расследовать нечем

ПОСЛЕ (версионируемое сохранение):
    plan v1  43 симв.   снимок перед правкой
    plan v2  3707       восстановление после укуса
    plan v3  43         откат к v1        ← откат сам стал НОВОЙ версией
```

История **append-only**: откат ничего не переписывает, он дописывает. «Кто и когда затёр» становится
вопросом с ответом.

⚠️ **Честная граница:** R7 защищает только то, что происходит ПОСЛЕ его включения. Затёртое раньше
не воскресает — в укусе это видно прямо: `v1` зафиксировал уже испорченное тело, потому что порча
случилась до версионирования. Это довод включать раньше, а не позже.

## §5 Что закрыто, а что нет

| | Состояние |
|---|---|
| **F3** смерть без свёртки + дрейф | ✅ закрыт механизмом: факты не переписываются руками и не протухают |
| **F11** слепок без истории | ✅ закрыт: append-only версии + откат как новая версия |
| **F15** окно между read и ack | 🟡 частично: derived **показывает** оборванное чтение (и R16 больше не даёт потерять батч), но само окно остаётся |
| **F16** присутствие/ритм не переживает чат | 🟡 частично: derived показывает heartbeat и время, но **не различает** «ритм снят по слову» ⊥ «умер вместе с сессией». Полное решение — поле присутствия в схеме, этап Э-В |

## §6 Что предлагается COORD (живое — его зона)

1. **`derive` как read-only команда рядом с `read-phoenix`** — ничего не меняет, добавляет
   пересобираемый слой к воскрешению. Самый безопасный первый шаг.
2. **Версионирование при сохранении** (`phoenix_history`) — аддитивная таблица, старый
   `save-phoenix` продолжает работать; включать лучше раньше (см. §4).
3. **Разгрузка ручных секций** — по мере доверия к derived: из `state`/`plan` уходят строки,
   которые машина собирает точнее. Это снимает основную часть из 184 КБ ручного текста.
4. Различение «ритм снят по слову» ⊥ «умер с сессией» (F16) — отдельным словом, вместе с Э-В.
