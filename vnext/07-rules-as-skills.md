# Правила как навыки (skills): помнить, ЧТО есть, а не ЧТО написано

Черновик решения · PROTO · 2026-08-21 23:30 UTC · статус: ЖДЁТ СЛОВА ВЛАДЕЛЬЦА

## 1. Боль, из которой это растёт (словами владельца)

Роли обязаны помнить правила целиком. Контексты растут, и со временем роль забывает
и применять правило, и то, что оно существует. Свод сегодня — 50 живых правил,
112 238 знаков; читается он по запросу (`set-rule.py --show`), но чтобы спросить,
надо ПОМНИТЬ, что и когда спрашивать. Это дисциплина, а у дисциплины в этом контуре
доказанная цена: она не масштабируется.

## 2. Что такое skill механически — и почему он попадает ровно в эту боль

Skill (навык Claude Code) — папка `<имя>/SKILL.md`: шапка с именем и ОПИСАНИЕМ-триггером
плюс тело. Устройство загрузки — то, ради чего всё:

```
СПИСОК описаний ..... в контексте КАЖДОЙ сессии, всегда — по строке на навык
ТЕЛО ................ грузится ТОЛЬКО когда навык позван: моделью по описанию
                      (задача подошла) или человеком через /имя
```

⇒ Роль постоянно носит не 112 тысяч знаков правил и не обязанность помнить их,
а десяток строк-напоминаний «такое есть; когда делаешь X — позови». Полный текст
приходит В МОМЕНТ применения — свежий, одинаковый у всех ролей.

⚖️ ЧЕСТНАЯ ПОЛОВИНА: правила и сегодня не сидят в контексте — они в базе. Skills чинят
не объём, а ЗАБЫВАНИЕ: (а) напоминание о существовании становится встроенным и бесплатным;
(б) текст читается в момент задачи, а не при пробуждении, когда он вылетит первым;
(в) один навык-пакет заменяет три-пять отдельных запросов к своду.

## 3. Главное решение: источник правды остаётся в базе

Правило `milestone-single-source` («один источник — один текст») запрещает вторую
рукописную копию. Поэтому:

```
БД (rules) .......... единственный источник: замки владельца, происхождение, снятие
SKILL.md ............ ПОРОЖДАЕМАЯ витрина — собирается генератором из БД,
                      руками не правится (в шапке пометка), как generated/sync.rules.md
                      и карточка роли
генератор ........... rules-to-skills.py: правило(а) пакета → тело SKILL.md
сторож .............. в общем прогоне: правило менялось ПОСЛЕ сборки навыка → красное
                      (тот же класс, что «посев свода отстал от живого» — уже оплачен)
```

Где лежат: `<контейнер>/.claude/skills/` — все роли работают в одном контейнере
и видят навыки автоматически. Канон для посева новых контуров: `gordipack/skills/`.

## 4. Какие правила переезжают — и какие НЕТ

Правила делятся на четыре рода, и переезжает только один:

```
А. ПРОЦЕДУРЫ ........ «когда делаешь X — вот как» — ПЕРЕЕЗЖАЮТ: у них есть триггер
Б. ПОСТОЯННЫЕ ....... UTC везде · один писатель · чужие контуры не читаем · ядро
   запреты           разрушающего · ядро общепонятных слов — НЕ переезжают: они нужны
                     всегда, «позвать в нужный момент» для них не существует.
                     Остаются короткими правилами; их стерегут механические проверки
В. ДАННЫЕ ........... состав ролей · зоны · карта файлов — ни правило, ни навык:
                     СПРАШИВАЮТСЯ запросом (в 18-тысячном правиле о ролях правила — на
                     тысячу знаков, остальное данные, которым место в таблицах)
Г. ПРОДУКТОВЫЕ ...... про наш код и стенд (миграции только у CORE, посев понятий,
                     семантический канон) — остаются правилами контура; наружу не едут
```

## 5. Девять навыков-пакетов (род А, ~68 из 112 тысяч знаков)

| Навык | Триггер (описание, всегда в контексте) | Какие правила внутри |
|---|---|---|
| ответ-владельцу | перед КАЖДЫМ ответом владельцу | формат ответа · вопросы вариантами · шаги на выбор · перемер перед вопросом · словарь запретных слов |
| синк-с-коллегами | читаю ленту / решаю, отвечать ли | лента целиком · отклик «взял/не возьму» · эскалация по молчанию · вывод не обрезать |
| записка-в-ленту | пишу записку | формат · приоритет по сроку читателя · объявление всем · только дописывать |
| коммит-и-отправка | перед git commit / push | зелёные проверки до коммита · поимённый add в общих репо · состав ветки · напоминание о разрушающем |
| шаг-схемы | правлю схему/миграции | шаг записывает себя · идемпотентность · ловушка наблюдающего сервиса |
| правка-общего | правлю общий инструмент/договор | объявить до правки · договор-дифф до кода · версия тем же ходом |
| приёмка-и-проверка | пишу проверку или сужу её вывод | приёмка по телу · различающие случаи и встречные пары · три исхода · молчащий отказ · содержимое-не-байты · форма договора живым вызовом · «не смог прочитать» ≠ «пусто» |
| память-и-перерождение | сохраняюсь / просыпаюсь / завожу роль | сохранение дополняет · стандарт памяти · ритм первым ходом · приданое с источником · список своих ошибок |
| карточка-задачи | завожу/веду/закрываю карточку | задача не живёт в чате · три разных остановки · критерий до работы |

Ядро каждого правила рода Б при этом ОСТАЁТСЯ в своде — навык не отменяет правило,
а разворачивает его в момент применения.

## 6. Чего skills НЕ чинят — названо до внедрения, а не после

```
① Срабатывание по описанию ВЕРОЯТНОСТНО. Модель может не позвать навык. Поэтому:
   · железные запреты (разрушающее, чужие контуры, UTC) НЕ переезжают из постоянного
     контекста; · судьёй остаются механические проверки — они и сегодня ловят то,
     что роль забыла. Навык снижает частоту забывания, а не заменяет сторожей.
② Описания могут расползтись. Десять описаний по три строки — уже треть страницы
   в каждом контексте: возвращается та же беда меньшего размера.
   Граница: описание ≤ 2 строк, сторож длины в общем прогоне.
③ Навык — снимок на момент сборки. Правка правила без пересборки делает навык
   лгущим тем же способом, каким лгал посев свода («версия 1 отвечает не на тот
   вопрос»). Лечение то же: генератор + сторож расхождения, руками не править.
```

## 7. Этапы — по слову владельца, не раньше

```
Э-1  ПИЛОТ (моя рука): генератор + сторож + ТРИ навыка — ответ-владельцу,
     приёмка-и-проверка, синк-с-коллегами. Неделя. Замер, а не впечатление:
     формат ответов владельцу · дубли в ленте · находки проверок о забытых правилах.
Э-2  Остальные шесть пакетов; роли получают их без действий — контейнер общий.
Э-3  Посев: gordipack/skills для новых контуров; соседним контурам — запиской.
```

Откат дешёвый: навыки — файлы; удалить папку = вернуться к сегодняшнему устройству,
свод в базе не менялся.
