## §1 Что проверяли

(1238 нот, 8 ролей, история с 2026-07-11), а не на синтетике. Стенд поднят из живого снимка
нарочно: миграционный шим извлечения адресатов обязан быть проверен на настоящей прозе.

## §3 Что подтвердилось качественно

1. **Причина ритуала снята, ритуал сохранён.** Разрезанный ACK-токен оставлен без изменений
   (он дёшев и доказал себя), но он больше **не борется с объёмом** — объём снят конструкцией.
   Проверено: цикл `index → ack` двигает курсор `2204 → 2391`; **повторный ack тем же токеном
   отклонён** (одноразовость держится).
2. **Знание о существовании ноты стало неотчуждаемым.** Курсор двигается по прочитанному ИНДЕКСУ;
   тело доступно по id всегда. Сегодня всё, что осталось за лимитом, уходит из поля зрения роли
   вместе с батчем.
3. **Миграционный шим работает на настоящей прозе.** Адресаты извлечены из тел (`@РОЛЬ`) — тот же
   код станет одноразовым backfill'ом при переходе. У RCC из 461 ноты лично адресованы **18**;
   то есть роль сегодня читает ~460 нот, чтобы найти 18. Это и есть корень перегрузки —
   не объём как таковой, а **отсутствие адреса**.
4. **Защита живого умеет краснеть** (`TEST-MUST-BE-ABLE-TO-FAIL`): прототип, натравленный на боевой
   путь, отказывается работать с exit=1. Проверено прогоном, не декларацией.

## §3а 🆕 Побочная находка — F14: приоритет инфлировал

В долге RCC **93 ноты из 461 (20 %)** несут `high`/`critical`. Приоритет **самоназначаемый автором**
и ничем не ограничен ⇒ он перестал сортировать: когда каждая пятая нота «критична», признак не несёт
информации. Требование **R14**: приоритет должен быть либо дефицитным ресурсом (квота на роль/сутки),
либо производным от структуры (адресовано лично + требует действия + есть дедлайн), а не свободным
полем. Заносится в карту боли как F14.

## §4 Доказательство неприкосновенности живого субстрата

Замер после всех прогонов (read-only):

```
живой курсор RCC: ('RCC', 2204, '2026-07-16 20:04:06')   ← не двигался, дата 16.07
роли в phoenix:   COORD CORE ING OPSSRE PROTO RCC STUD TAXO   ← все UPPERCASE, расщепления нет
guard-all:        то же единственное красное, что и до работы (свежесть чужих слепков)
```

Песочница поднята через `src.backup(dst)` из соединения `mode=ro` — при **активном WAL** живой БД
(файловая копия дала бы рваный снимок; проверено, WAL был активен в момент съёмки).
Сверка снимка: 18 таблиц + 1 VIEW, счётчики строк совпали по всем таблицам.

## §5 Границы прототипа (честно)

- Это **срез одного механизма** — чтения. Запись ноты с адресатами, производный слепок, схема
  v-next и миграция ещё не прототипированы.
- `digest` группирует по дням и адресату; **смысловой** свёртки («что решено за период») он не даёт
  и без LLM-слоя не даст. Не обещаю больше, чем умеет.
- Шим `@РОЛЬ` разбирает прозу регуляркой: он для миграции, а не для постоянной жизни. В v-next
  адресаты пишутся полем при записи ноты.
- Невнимательность в середине индекса не ловится ничем — граница класса, названа в `01`, §4.
