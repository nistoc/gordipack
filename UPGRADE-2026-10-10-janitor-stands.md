## Зачем этот выпуск

Приёмки оставляют во временной папке Windows каталоги с копиями базы координации. У эталона на 10.10
их больше пяти тысяч, ≈109 ГБ. Ручной уборщик `janitor-stands.py` видел не все: начала имён, которые
проверки задают f-строкой или передают переменной, ему были невидимы. Замер эталона 10.10 09:07–09:12 UTC
(только показ, ничего не удалено):
```
прежняя редакция ..... 269 начал имён · под порог «старше суток» 4 862 каталога · 96,02 ГБ
новая редакция ....... 283 начала (с каталогом приёмок пакета) + названные руками m509- и m536-
                       · под порог 5 132 каталога · 108,59 ГБ
```
Заодно закрыты две опасности: уборщик брал начало «…» из собственного комментария, а первое же короткое
начало вроде «g» снесло бы каталог `gordi` — общий корень стендов, задуманный для этапа Э6.

## 1. Что изменилось

```
f-строка ................. prefix=f"bite-birth-{x}-" даёт начало «bite-birth-» (раньше — ничего)
комментарии .............. пример вызова в комментарии больше не даёт начала имени (разбор tokenize);
                           «#» внутри строки — не комментарий
--prefix НАЧАЛО .......... добавить начало руками, можно повторять: для проверок, которые передают начало
                           переменной (m509- и m536- у bite-milestone-step-set.py)
каталог gordi ............ в корне временной папки не берётся ни при каком начале — строка «🔒 не трогаю gordi»
начало короче 4 знаков ... не берётся и называется строкой «НЕ взяты (короче 4 знаков …)»
удаление ................. справка и показ говорят прямо: --apply удаляет НАВСЕГДА, мимо Корзины
```

## 2. Какие файлы меняются

```
vnext/prototype/janitor-stands.py ........ уборщик (правки раздела 1; имена кода по-английски,
                                           прежнее имя функции каталоги_инструментов — синоним)
vnext/prototype/bite-stand-cleanup.py .... приёмка: случаи (12)–(16), у каждого своя нарочная поломка; 16 из 16
```
Оба файла лежат во втором каталоге установки (ключ `prototype_install_dir`, документ 09.10) — обновление
приносит их, если они у вас уже стоят. Ставить их надо ВМЕСТЕ: новая приёмка зовёт новые имена функций.

## 3. Порядок для вашего контура

```
1 ... план:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev be6760b
      ожидаемо «≠» у janitor-stands.py и bite-stand-cleanup.py
2 ... запись, второй план — до «+ ≠ ≈» нет:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev be6760b --apply
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev be6760b
3 ... приёмка (из второго каталога установки):
        python <каталог приёмок>/bite-stand-cleanup.py
      → последняя строка «ПРИЁМКА ПРОЙДЕНА — случаев 16»
```

## 4. Уборка — только рукой человека

Утилита по умолчанию только ПОКАЗЫВАЕТ. Удаление — навсегда, мимо Корзины, поэтому `--apply` запускает
человек, а не роль. Сначала показ, потом то же с `--apply`:
```
python <каталог приёмок>/janitor-stands.py --tools-dir <каталог приёмок> <КОНТУР>/.mezosync/scripts <клон пакета>/vnext/prototype --prefix m509- --prefix m536-
```
`--tools-dir` с клоном пакета нужен, чтобы взять начала приёмок, которых у вас не стоит (например,
`bite-target-sel-` у `bite-target-selection.py`). Порог — сутки: каталоги идущих сейчас прогонов моложе
и не трогаются.

## 5. Известно и в этом выпуске НЕ сделано

- Утилита не отличает СВОИ каталоги от каталогов соседнего контура на той же машине: у них одна временная
  папка и одни начала имён. Старше суток уйдут и они. Различение по владельцу каталога — этап Э6 (карточка #680).
- Каталоги, на которые ссылаются старые записки и карточки как на доказательства, уйдут вместе с остальными:
  отдельного места для доказательств нет (выбор владельца эталона 10.10, карточка #671 — только
  предупреждение о путях во временную папку при записи).
- Автоматической уборки нет: её место — этап Э6 (карточка #680).
