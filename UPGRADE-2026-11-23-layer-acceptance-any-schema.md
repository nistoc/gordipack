## 2. Что увидит контур

В начале вывода приёмки — новые строки:

```
   половины испытуемого: дерево пакета <клон>
   схема источника (MEZO_LIVE_DB): со слоем — снято приёмкой: полей 3 из 3, указатель да, запись журнала шага да
```

У строки «схема источника» три вида: «без слоя — снимать было нечего» · «полей и указателя слоя нет, но журнал
называет шаг применённым — запись журнала снята приёмкой» (так выглядит копия, с которой поля сняли рукой по
разделу 4 прежнего документа) · «со слоем — снято приёмкой: …». С каталогом инструментов контура вместо первой
строки — «каталог инструментов … · инструменты памяти — из каталога приёмки …» и строка «стенд: каталог
инструментов скопирован на стенд деревом пакета», а в конце вывода — строка «⚠️ Установленные в контуре
инструменты памяти (vnext-tools) эта приёмка НЕ испытывает …».

У случая ⑦-1 в строке — часть «сличение с источником: снято ровно заведённое шагом, прочее как в источнике».

Строка итога:

```
ИТОГ: ④ 16 из 16 · ⑥ 6 из 6 · ⑦ 1 из 1 · ② ③ 4 из 4 · поломки 14 из 14
```

В наборе ядра — новая строка:

```
✅  bite-memory-layers.py                    было 0 · 56 · 0 · стало 0 · 56 · 0 · совпало · 56 с
```

## 3. Порядок установки

Ставить нечего: `update-tools.py` обновляет в `vnext-tools` только файлы, которые там уже лежат, а приёмки
`bite-memory-layers.py` и списка `core-bites.txt` там нет. Набор ядра и приёмку запускают из клона пакета.

## 4. Проверка

Из клона пакета на merge commit выпуска; `MEZO_CONTAINER` нужна, когда клон лежит вне контура:

```
MEZO_CONTAINER=<каталог контура> python -u -X utf8 <клон>/vnext/prototype/bite-all.py --set core --only bite-memory-layers
```

Ожидаемо — код 0 и «совпало 1 · разошлось 0 · не запустилось 0». Приёмку можно звать и напрямую, на дереве
клона, — схема годится любая, в том числе схема самой живой базы (её приёмка только читает):

```
MEZO_SCRIPTS_ROOT=<клон>/scripts MEZO_LIVE_DB=<живая база> MEZO_CONTAINER=<каталог контура> \
    python -u -X utf8 <клон>/vnext/prototype/bite-memory-layers.py
```
