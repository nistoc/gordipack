## 2. Что увидит контур

Новые строки печатает уборка стендов по сроку (и любой, кто зовёт помощник рукой). Каждая — про один каталог:

```
⛔ не перенесено в Корзину, каталог не тронут: <путь> — путь внутри — N знаков UTF-16, а Windows берёт
   в Корзину не длиннее 259 (самый длинный: <путь>); Корзина такой каталог не берёт, Windows стёрла бы его насовсем
⛔ не перенесено в Корзину, каталог не тронут: <путь> — записи Корзины не читаются: <каталог> (<ошибка>)
⛔ УДАЛЕНО МИМО КОРЗИНЫ: <путь> — каталога нет на месте, а записи с его прежним путём в Корзине не появилось:
   вернуть его из Корзины нельзя. Перенос остальных остановлен
⚠️ каталога нет на месте, а приход в Корзину не проверен: <путь> — новая запись Корзины не прочитана.
   Перенесённым не засчитан, перенос остальных остановлен
⏸ не перенесено, каталог не тронут: <путь> — перенос остановлен: <причина>
```

Сводная строка уборки прежняя: каталог с любым из этих исходов входит в её число «не перенесено».

⚠️ **Стенд с путём от 260 знаков внутри уборка по сроку больше не уберёт никогда**: каждый час он получает отказ
и строку выше. Убирать такие стенды — рукой человека, утилитой `janitor-stands.py --apply` (она удаляет
насовсем, мимо Корзины, и говорит это сама). Прежде такой стенд, если его дерево было той формы, что в опыте
раздела 5, тоже исчезал насовсем, но молча и под словом «в Корзину».

ℹ️ Первая строка выше называет предел 259 знаков как общий для Корзины — это шире замера (см. «Зачем»): для дерева
с длинным путём у файла прямо в каталоге Windows берёт и длиннее. Строку печатает установленный помощник; третий
выпуск его не меняет, текст поправится при следующей правке `mezo_stand.py`.

⚠️ Строка «УДАЛЕНО МИМО КОРЗИНЫ» значит, что каталог уже потерян: помощник ловит это ПОСЛЕ переноса и
останавливает остальные. Причины, кроме длинного пути, у эталона не встречались; если строка появилась —
пришлите её PROTO контура-эталона.

## 4. Проверка после установки

Приёмку запускают из клона пакета на merge commit выпуска: рядом с ней в `vnext/prototype` лежит `mezo_stand.py`,
она испытывает именно его. Тот же файл установлен во второй каталог контура — после установки они совпадают.

```
git clone https://github.com/nistoc/gordipack.git <клон>
git -C <клон> checkout <merge commit>
python -X utf8 <клон>/vnext/prototype/bite-recycle-bin-checks.py
```

Ожидаемо — код 0 и две последние строки:

```
ИТОГ: случаев прошло 9 из 9 · провалено: нет · не проверено: нет · поломок поймано 10 из 10
Настоящая Корзина: прогонов ⑥ 11 (целый помощник и каждая поломка) · записей с путём внутри каталога приёмки: 0
```

Настоящая Корзина в приёмке только читается. В случае ⑥ вызов переноса Windows (SHFileOperationW) подменён
счётчиком, поэтому перенос не доходит до Windows ни на целом помощнике, ни под любой поломкой. Вторая строка
считает это по записям настоящей Корзины; сам счётчик испытан в случае ① на подставном томе.

```
① ①б ..... запись $I с прежним путём — засчитан; ①б — каталог назван коротким именем 8.3, запись несёт полное
② ②б ..... 260 знаков — отказ до переноса; 259 — до переноса дошло
③ ③б ④ ... записи нет — «УДАЛЕНО МИМО КОРЗИНЫ»; ③б — запись есть, но о соседнем каталоге — тоже «мимо»;
           запись незнакомого формата — «приход не проверен»; во всех трёх второй каталог не тронут
⑤ ........ записи Корзины не читаются — отказ, перенос не звался
⑥ ........ настоящая уборка по сроку через _windows_bin: старый стенд с путём 260 знаков — отказ, стенд на месте,
           в строке уборки «не перенесено: 1», перенос Windows не звался, в настоящей Корзине записей из каталога ⑥ нет
```

На томе без коротких имён 8.3 случай ①б и поломка П1б не различают: код 2, «не проверено: ①б». Это не провал.
