# hooks/ — впрыски в контекст агента (host OS)

Два хука, оба ставятся в `~/.claude/settings.json` на host OS и работают
для ВСЕХ чатов машины:

| Файл | Что впрыскивает |
|------|-----------------|
| [`time-injection.json`](./time-injection.json) | реальное время (агент часов не имеет) |
| [`owner-reply-reminder.json`](./owner-reply-reminder.json) | напоминание формы ответа владельцу — в каждый ход каждого чата, принадлежащего КОНТУРУ |

## owner-reply-reminder — напоминание формы ответа владельцу

Реализует правило [`owner-reply-format`](../rules/universal.sql). Оплаченный урок:
после каждого пересоздания роли забывали форму ответа — правило лежало в своде,
но свод не читается сам. Навык «по вызову» не спасает: его надо не забыть позвать.
Держит только впрыск в КАЖДЫЙ ход.

Как работает: хук поднимается от текущего каталога чата вверх, пока не встретит
`.mezosync/mezosync.db` — признак контура. Нашёл — впрыскивает каркас формы и команду
чтения ЖИВОГО правила из свода ИМЕННО ЭТОГО контура; не нашёл — молчит. Полного текста
правила хук не несёт: скопированное тело — вторая редакция, расходится со сводом молча.

Парный навык host-уровня — [`skills/gordi-owner-reply`](../skills/gordi-owner-reply/SKILL.md):
разворачивает правило по вызову, тем же способом (живое чтение из свода контура).

Контурные добавки (пример: у Atlas — «времена только UTC с суффиксом») дописывайте
отдельной веткой `if ($d -like '<путь контура>*') { $extra = '…' }` — образец общий.

## time-injection — впрыск времени

Реализует универсальное правило [`timestamp-in-replies`](../rules/universal.sql):
каждый ответ агента начинается и заканчивается текущими локальными датой+временем,
чтобы владелец мог синхронизировать во времени чтение ответов разных агентов.

## Зачем hook, а не «просто попроси агента ставить время»

Агент **не знает** реального времени — модель не имеет часов. Единственный надёжный
источник — впрыск через hook. Два события:

| Hook | Впрыскивает | Когда |
|------|-------------|-------|
| `UserPromptSubmit` | `CURRENT_UTC_TIME=<yyyy-MM-dd HH:mm> UTC` + `CURRENT_LOCAL_TIME=<yyyy-MM-dd HH:mm:ss K>` + готовую метку «UTC (местное)» для начала ответа | в начале каждого хода |
| `PreToolUse` | `STEP_TIME=<HH:mm:ss>` (местное, без смещения!) | перед каждым вызовом инструмента (свежее!) |

С 29.08.2026 (слово владельца контура-донора) краевые метки ответа — пара
`12:53 UTC (14:53 местное)`: UTC считает сама машина (агент не делает арифметику —
класс «местное время под буквами UTC» закрыт построением), местный час идёт рядом
в скобках. Правило пары: `timestamp-in-replies` v3 в `rules/universal.sql`.

Без hook агент выдумает время — и метки будут врать. Именно поэтому правило
`timestamp-in-replies` ссылается на этот файл: правило без скрипта не работает.

## Установка

1. Открой `~/.claude/settings.json` (создай, если нет).
2. Слей ключи `hooks.UserPromptSubmit` и `hooks.PreToolUse` из
   [`time-injection.json`](./time-injection.json) в свой `hooks`-блок
   (если у тебя уже есть массивы под этими событиями — **добавь**, не затирай).
3. Перезапусти чат. Проверь: в начале ответа агент печатает `🕐 <дата время>`.

## Платформа

Команды написаны под **PowerShell** (`"shell": "powershell"`, Windows/Claude Desktop).
На macOS/Linux замени `command` на date-эквивалент, например:

```bash
printf '{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"CURRENT_LOCAL_TIME=%s. Print this exact time at the START of your reply, and print the current time again at the END."}}' "$(date '+%Y-%m-%d %H:%M:%S %z')"
```

## Замечание про Claude Desktop (Windows)

Встроенный UI-бейдж `showMessageTimestamps` на Claude Desktop для Windows **не
рендерится** — поэтому время печатается прямо в тексте ответа. На других клиентах
бейдж может дублировать метку; это не мешает.
