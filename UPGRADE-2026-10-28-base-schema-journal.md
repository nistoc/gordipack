## Зачем этот выпуск

Контур, собранный из базовой схемы v6 (с выпуска «12.10, второй», `e50ed9d`), нёс в журнале шагов `schema_migrations`
одну строку `v6`. Контур из v5, обновлённый теми же шагами, несёт `v5`, одиннадцать шагов и `v6`. Структура у них
одинаковая, а журналы разные — и приёмка `bite-messages-archive.py` проваливала случай ⓪ на каждом новом контуре: она
ждёт строку `20260905-messages-archive`. Найдено cloud session при работе над PR #45 (описание PR #45, 2026-10-27).

## 1. Что изменилось

```
schema_step_order.py ...... новый список BASE_STEPS — журнал, который несёт сам файл базовой схемы: веха v5, 11 шагов,
                            веха v6 (13 имён; последнее — веха самой базовой схемы)
init-group.py (блок 6а) ... новый контур пишет строки BASE_STEPS ДО строки вехи — готовой функцией журнала с пометкой
                            «записано задним числом» (backdated), автор — сборщик. Список, который не кончается вехой
                            этой схемы, не пишется вовсе: предупреждение и итог «с отказами». Строка итога сборки
                            называет «строк до вехи (вшитое в схему) N»
bite-shown-count.py ....... NameError на одной строке исправлен: приёмка снова запускается
```

**Правило для следующей базовой схемы (v7 и дальше):** `BASE_STEPS` не укорачивают, а дописывают в конец шагами `STEPS`
до новой вехи включительно, тем же commit убирая эти шаги из `STEPS`. Журнал стенда новой базы включает журнал прежней.
Тест `tests/test_base_schema_journal.py` это проверяет.
