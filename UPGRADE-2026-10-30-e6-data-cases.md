## Зачем этот выпуск

Набор ядра (`core-bites.txt`, прогон `bite-all.py --set core`) держит для каждой приёмки три числа: код выхода,
число знаков «✅» и число знаков «🔴» в её выводе. Цель этапа Э6 — одни и те же три числа на любом контуре, если код один и тот же.
Три случая этому мешали: их итог решали данные контура, а не испытуемый код.

```
bite-two-locks.py ⑪ .............. дата замера в тексте отказа сверялась с записанной в живой базе запиской-источником.
                                   На контуре без этой записки случай пропускался, а где под тем же номером
                                   лежит другая записка (AIA) — проваливался
bite-printed-forms-sources.py ⓪ .. без CLAUDE.md в контуре (свежая сборка его не несёт) случай пропускался: код 2 и
                                   47 из 47 против 48 из 48 у контуров с CLAUDE.md
bite-brief-views.py ⑩ ............ сводка моста соседей судилась по соседям из живой базы. На контуре без соседей
                                   случай судил другую ветку («вопросов нет вовсе»): 0 · 16 · 0 против 0 · 17 · 0
```

## 3. Порядок для вашего контура

```
0 ... резервная копия — UPGRADE.md, раздел 3, шаг 0
1 ... план:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <вершина main>
      ожидаемо «≠» у тех из трёх приёмок, что у вас установлены (замер: план у эталона, стоящего на afe5634, против
      90852f4 — три строки «≠ … → второй каталог»: bite-brief-views.py, bite-printed-forms-sources.py,
      bite-two-locks.py; против afe5634 — «инструменты совпадают с источником»).
      «✋» — вы правили файл у себя: остановитесь и пришлите вывод
2 ... запись, второй план — до «+ ≠ ≈» нет:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <вершина main> --apply
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <вершина main>
2½ . реестр известного долга проверки среды вызовов — только если у вас есть файл
      <второй каталог>/acceptance-env-debt.txt (в пакете его нет, его ведёт контур). В bite-two-locks.py функция
      «прогон» переименована по-английски, а ключ строки реестра — «файл :: функция :: инструмент», так что
      check-acceptance-env.py назовёт этот вызов новым. Вызов тот же, число то же — поправьте имя функции во втором
      поле строки:
        bite-two-locks.py ... прогон → run_copy
      проба: python <КОНТУР>/<второй каталог>/check-acceptance-env.py — «новых: 0», строк «долг уменьшился» нет.
      У остальных двух приёмок ключи реестра не менялись (замер у эталона — раздел 4)
3 ... шагов схемы нет — шаг 2 раздела 3 UPGRADE.md пропустите
4 ... приёмки из клона вершины main с vnext/local/paths.json вашего контура (не из выгрузки git archive):
        python <КЛОН>/vnext/prototype/bite-all.py --set core --only bite-two-locks
        python <КЛОН>/vnext/prototype/bite-all.py --set core --only bite-printed-forms-sources
        python <КЛОН>/vnext/prototype/bite-all.py --set core --only bite-brief-views
      ожидаемо у каждой «совпало»: 0 · 12 · 0 · 0 · 48 · 23 · 0 · 18 · 0 — одинаково на любом контуре.
      Без переменной MEZO_CONTAINER: приёмки берут испытуемые инструменты из вашего контура по файлу путей клона
```
