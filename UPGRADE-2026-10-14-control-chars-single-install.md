## Зачем этот выпуск

**Выпуск 2740aaf обещал больше, чем делал (находка контура AIA, письмо 2026-10-14 02:00 UTC).** С 2740aaf
`guard-control-chars.py` без аргументов берёт ещё папки `coordination` и `bridges`. Корень контейнера он узнавал
только по одному признаку — `.mezosync` рядом с каталогом инструмента, то есть по раскладке
`<контейнер>/vnext-tools/`. У контура без второго каталога установки единственная копия лежит в
`<контейнер>/.mezosync/scripts/`, признак не срабатывал, и проверка брала один каталог инструментов. Код 0,
«мин 0» — по виду то же, что у эталона.

Самопроверка строила только раскладки `vnext-tools` и `vnext/prototype`, приёмки автора и не автора шли на той же
раскладке — ошибку не поймал никто, кроме контура с другой раскладкой. Шаг 4 раздела 3 документа 2740aaf («в
перечне ваши папки coordination и bridges») для такого контура был неверен.

## 1. Что изменилось

```
guard-control-chars.py .... корень контейнера узнаётся по ДВУМ признакам: .mezosync рядом с каталогом инструмента
                            (раскладка vnext-tools, как прежде) ИЛИ сам каталог инструмента — .mezosync/scripts
                            (единственная копия). Выше своего корня обход по-прежнему не идёт.
                            --selftest: контрастов 23 → 27 — раскладка «единственная копия» (папки взяты; папка
                            без .mezosync и папка соседнего контейнера — нет) и встречный: каталог scripts НЕ под
                            .mezosync корнем не считается
```

## 2. Какие файлы меняются

```
vnext/prototype/guard-control-chars.py .... проверка невидимых управляющих байтов (её зовёт guard-all.py)
```
Обновление приносит файл туда, где он у вас стои́т: во второй каталог установки или, если второго каталога нет,
в `.mezosync/scripts`.

## 3. Порядок для вашего контура

```
0 ... резервная копия — UPGRADE.md, раздел 3, шаг 0
1 ... план:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev 00df16a
      ожидаемо ровно 1 строка «≠» — guard-control-chars.py (у эталона — тоже 1).
      «✋» у него — вы правили его у себя: остановитесь и пришлите вывод
2 ... запись, второй план — до «+ ≠ ≈» нет:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev 00df16a --apply
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev 00df16a
3 ... шагов схемы нет — шаг 2 раздела 3 UPGRADE.md пропустите
4 ... проверки — из каталога, где у вас стои́т guard-control-chars.py:
        python <каталог>/guard-control-chars.py --selftest
      → «самопроверка: все 27 контрастов прошли»
        python <каталог>/guard-control-chars.py
      → первой строкой «каталог не назван — беру по умолчанию: …»; в перечне — ваши папки coordination и
        bridges (прямо в корне контейнера и в <репозиторий>/.mezosync/), при ЛЮБОЙ из двух раскладок.
      ⚠️ Местную обёртку для этих папок (у AIA — в local/) убирайте после того, как находки двух прогонов совпали
```

⚠️ Если общий прогон у вас до сих пор не смотрел папки координации, после установки он посмотрит их впервые.
Невидимый байт в старой записи или письме даст провал этой строки — это находка, а не поломка выпуска: файл и байт
названы в выводе, лечение — `--unescape` или `--fix` (шапка `guard-control-chars.py` объясняет, какое когда).
