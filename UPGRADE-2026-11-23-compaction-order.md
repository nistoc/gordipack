## 2. Что увидит контур

У каждого сжимаемого раздела после строки «было … → стало …» — новая строка:

```
    порядок ухода: время в разделе — свежее сверху (пар записей с часом: свежее выше 1749, ниже 219) · свежих с 2026-11-22: 3, 48045 знаков — сжатие их не уносит
```

Направление — «свежее сверху», «свежее снизу» или «не определено». Причины у унесённых записей:

```
снята с хода
старшая по часу: <дата>
без часа, по соседней записи с часом #<номер> ≈ <дата>, место <место в разделе>
без часа, время в разделе не определено — снизу вверх, место <место в разделе>
```

Если без свежих порог не достигнут — код 3 и строка:

```
    ⚠️ порог НЕ достигнут: осталось <N> знаков при пороге <порог> — в слое остались только свежие записи — <число>, <N> знаков: сжатие их не уносит
```

⚠️ **У раздела, где свежие записи сами больше порога, сжатие уносит ВСЕ несвежие.** Так у COORD (раздел 5):
одна свежая запись раздела state — 45 226 знаков при пороге 20 000. Сжатие тогда уносит в warm 188 записей
из 191, и слой всё равно не укладывается. Прежний порядок в той же базе уносил все три свежие записи вместе
с этой. Унесённое не пропадает: текст записей и раздела не меняется, меняется поле слоя, и до этапа Э4
пробуждение читает раздел целиком. Перед настоящим сжатием смотрите перечень холостым прогоном (`--dry-run`).

ℹ️ **В день первого разбора раздела** все его записи без часа появились в слое сегодня. Сжатие их не унесёт
до послезавтра (UTC) — это цена меры «по появлению», а не сбой.

⚠️ **Схема из живой базы, где шаг слоя уже применён, приёмке не годится**: она отвечает кодом 2 («в схеме,
взятой с MEZO_LIVE_DB, поле слоя УЖЕ есть»), потому что сама наводит шаг слоя на подставную базу. Базу со схемой
без поля слоя готовят одной командой из схемы живой (строк в ней нет):
