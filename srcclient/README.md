# `/srcclient` — интерфейс просмотрщика координационной базы (фронтенд)

**Черновик.** React + TypeScript + Vite. Работает поверх локального сервиса из соседней папки
[`/src`](../src/README.md) — сам к базе не обращается и обращаться не может.

## Запуск

Нужны **два** процесса. Сначала бэкенд:

```bash
dotnet run --project src/Gordi.Viewer.Api -- --db C:/путь/к/mezosync.db
```

Потом интерфейс:

```bash
cd srcclient
npm install      # один раз
npm run dev      # http://localhost:5173
```

Запросы `/api/*` Vite проксирует на `http://127.0.0.1:5177` (см. `vite.config.ts`). Порт бэкенда
другой — задай `VITE_API_PORT` или поправь конфиг.

```bash
npm run build      # сборка в dist/ (проверяет типы перед сборкой)
npm run typecheck  # только типы
```

## Что показывает

| Вкладка | Состояние | Что там |
|---|---|---|
| **Задачи** | 🎯 основное | карточки бэклога; открытые **без критерия приёмки** подсвечены и идут первыми; фильтры по статусу, роли и «только без критерия»; разворот карточки — описание, события, проверки, связанные записки |
| Лента | заготовка | записки страницами, фильтр по автору/важности, поиск подстрокой, разворот тела |
| Роли | заготовка | состояние, курсор, число записок, секции памяти — с пометкой, каких источников в базе нет |
| Правила | рабочее | правила **сгруппированы по смыслу**, у каждой группы — заголовок, число и описание простым языком; группы сворачиваются; **отозванные вынесены отдельной группой** и свёрнуты по умолчанию; на карточке — чьё решение, при каком условии отменяется, основание |
| Схема | заготовка | что в базе есть, чего нет против эталона, версия схемы |

Шапка: выбор базы из найденных бэкендом, «обновить сейчас», отметка **только чтение**,
время последнего перечитывания.

## Правило, которое здесь важнее вёрстки

**Пустое место обязано быть подписано.** Если в базе нет колонки `backlog.done_when`, интерфейс
пишет «поля нет в базе», а не оставляет прочерк и не рисует `0`. Ноль в плитке «открытых без
критерия» читался бы как хорошая новость, а означал бы «посчитать было нечем».
Ради этого в контракте заведён тип `Measure` (значение + признак «поддерживается»), а в
`components/MeasureValue.tsx` — единственное место, где он превращается в число или в «н/д».

**И то же правило про ПУСТОЙ ЭКРАН.** Замер 2026-08-08 23:26 UTC: страница «Схема» показывала
пустоту — ноль элементов в `#root`, ноль символов текста. Причина — одно неверное имя поля в
описании ответа сервиса: обращение к несуществующему полю бросало исключение прямо во время
отрисовки, а React в таком случае снимает с экрана ВСЁ дерево, вместе с вкладками и шапкой.
Сообщение оставалось только в консоли браузера, куда смотреть никто не обязан.

Отсюда `components/ErrorBoundary.tsx` и две границы: внешняя вокруг всего приложения и
внутренняя вокруг активной страницы. Упавшая страница теперь падает **одна** и **со словами** —
вкладки остаются, можно уйти на соседнюю. Имя поля починено отдельно: ловушка лечит не причину,
а класс отказа. Молчаливая пустота неотличима от «данных нет» — и пока она молчит, следующая
такая опечатка снова будет выглядеть как норма.

Поэтому у страниц «Схема» и «Правила» состояний **четыре**, и каждое названо словами:
жду ответа · ответ не пришёл · ответ пришёл и он пуст · вот содержимое.

## ⛔ Чего этот интерфейс НЕ делает

- **Ничего не меняет в базе.** Кнопок редактирования нет, и API их не предоставляет.
- **Не ходит в базу напрямую.** Только через `/api` соседнего сервиса.
- **Не рендерит markdown.** Тела записок и описания задач показываются как есть,
  моноширинным текстом. Разметка — отдельное решение, см. вопросы в отчёте.
- **Не помнит выбор между запусками.** Фильтры и активная вкладка живут в памяти страницы.

## Устройство

```
srcclient/
├── index.html
├── vite.config.ts          порт 5173 + прокси /api → 127.0.0.1:5177
├── src/
│   ├── main.tsx
│   ├── App.tsx             шапка, вкладки, общий опрос состояния
│   ├── api.ts              все обращения к бэкенду
│   ├── types.ts            формы ответов (держатся руками, генератора нет)
│   ├── usePolling.ts       периодический опрос: ошибка не гасит прежние данные
│   ├── format.ts           время — всегда UTC с явным суффиксом
│   ├── components/
│   │   ├── SourceBar.tsx   выбор базы, обновление, состояние
│   │   └── MeasureValue.tsx  число ИЛИ «н/д» — см. правило выше
│   └── pages/              TasksPage · FeedPage · RolesPage · RulesPage · SchemaPage
└── (node_modules, dist — под .gitignore)
```

Зависимостей намеренно минимум: нет маршрутизатора (вкладки — состоянием), нет библиотеки
запросов, нет CSS-фреймворка. Для пяти экранов черновика каждая из них добавила бы больше
настройки, чем сняла кода.

## Проверено на этой машине

Node v26.5.0, npm 11.14.1. Установилось и собралось: react 19.2.8, react-dom 19.2.8,
vite 7.3.6, typescript 5.9.3, @vitejs/plugin-react 5.2.0.
`npm run build` проходит (39 модулей, ~216 КБ JS до сжатия).

⚠️ **Чего НЕ проверено:** интерфейс ни разу не открывался в браузере — ни dev-сервер, ни
собранный `dist` не запускались. Проверены только типы и сборка. Всё, что видно глазами
(вёрстка, поведение фильтров, реальный ответ бэкенда), — замысел, а не результат.
