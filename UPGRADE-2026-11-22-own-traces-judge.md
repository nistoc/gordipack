```
      и не «провалилась»: найдите, почему база недоступна, и повторите прогон. Общий запуск приёмок

      приёмка отработала, не судился один контрольный случай
      Три вида строки с кодом 2 и что за каждой стоит:
        «⏳ НЕ ПРОВЕРЕНО: база контура недоступна с начала прогона (причина)» — база не читалась уже на первом
            вопросе; стенд не создавался, ни один случай приёмки не судился
        «⏳ … НЕ ПРОВЕРЕНО» у контрольного случая — база отвечала в начале и перестала к концу прогона;

      приёмки по непустому файлу базы; когда файла базы нет или он пуст, не находится сам контур, и отказ
```

Нарочная поломка у семи приёмок, судящих функциями помощника, ставится на стенде во ВСЕХ копиях `mezo_stand.py`,
а их там четыре: две в клоне пакета (`scripts/` и `vnext/prototype/`) и две установленные в контур стенда
(`<КОНТУР>/.mezosync/scripts/` и второй каталог установки). Копии не равноправны: `bite-rule-expiry.py`
и `bite-issue-loop.py` берут помощник из установленного каталога `<КОНТУР>/.mezosync/scripts/`, остальные пять —
из каталога приёмки в клоне. Поломка, поставленная только в клоне, первых двух не касается — они проходят,
и это читается как «поломка не ловится». Суду возвращается прежний способ, и провалиться обязан ровно встречный
случай «-а». Три правки в каждой из четырёх копий:

```python

class _StateDict(dict):
    state = None


def _file_state(db):
    out = []
    for name in (str(db), str(db) + "-wal"):
        try:
            st = os.stat(name)
            out.append((st.st_size, st.st_mtime_ns))
        except OSError:
            out.append(None)
    return tuple(out)
```

⚠️ Прогон под такой поломкой проваливается, а стенды провалившегося прогона приёмка по построению оставляет
