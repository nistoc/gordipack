# Приёмка ветки пакета чужой рукой — порядок

Для того, кто принимает чужую ветку gordipack и не знает её предыстории. Цель одна: чтобы
провал на экране значил поломку в правке, а не в стенде.

> Каждая строка раздела «Ловушки» получена прогоном, а не чтением кода (карточка #761:
> приёмки pull request 81 и 97, ноябрь 2026). Три ветки подряд приёмщик видел провал,
> причина которого была в стенде.

## Три исхода — не два

| что на экране | что это значит | код выхода |
|---|---|---|
| приёмка принята | свойство держится | 0 |
| случай провален | свойство сломано — либо стенд собран не так (см. «Ловушки») | 1 |
| не запустилась / отказ мерить | приёмке нечем мерить: нет контура, базы, аргумента | 2 |

Провал — ещё не находка. **Прежде чем нести его автору, прогоните ту же приёмку на том же
стенде по дереву без правки** (ветка `main`). Тот же провал на обоих — это стенд или прежний
долг приёмки, а не правка.

## Шаг 1. Взять ветку, не трогая чужой клон

```bash
git clone --branch <ветка> <адрес репозитория> <стенд>/gp
git -C <стенд>/gp rev-parse HEAD
```

- Берите **клон с историей**, а не выгрузку `git archive`: двум приёмкам набора ядра история нужна
  (`bite-fresh-circuit.py` на выгрузке даёт другие числа, `bite-update-tools-rev.py` не запускается —
  ей нужно не меньше восьми редакций `scripts/backlog.py`).
- Чужой клон и чужое рабочее дерево не трогайте: ни `checkout`, ни `stash`, ни запуск приёмок в нём.
- Запишите commit вершины: по нему ваш вердикт и будут читать.

## Шаг 2. Собрать стенд

Стенд — каталог-контейнер с **коротким путём**; пакет ветки лежит ВНУТРИ него.

```
<стенд>/                        ← контейнер
  .mezosync/mezosync.db         ← база контура: копия живой ИЛИ свежий контур из той же ветки
  .mezosync/scripts/            ← копия <стенд>/gp/scripts
  vnext-tools/                  ← копия <стенд>/gp/vnext/prototype (см. «Ловушки»: двум приёмкам нужно разное)
  gp/                           ← клон ветки из шага 1
  gp/vnext/local/paths.json     ← файл путей, шаг 3
```

База — одним из двух способов:

```bash
# копия живой базы — средствами sqlite, а не копированием файла
python -c "import sqlite3,sys; s=sqlite3.connect('file:'+sys.argv[1]+'?mode=ro',uri=True); d=sqlite3.connect(sys.argv[2]); s.backup(d); d.close(); s.close()" <живая база> <стенд>/.mezosync/mezosync.db
```

```bash
# свежий контур из ТОЙ ЖЕ ветки
python <стенд>/gp/scripts/init-group.py --name <имя> --path <стенд>/.mezosync --roles COORD
```

Инструменты контура в стенде (`.mezosync/scripts`, `vnext-tools`) берутся из той же ветки, что и
приёмки: иначе приёмка ветки судит инструменты другой версии.

## Шаг 3. Файл путей — один

```json
{"container": "<стенд>"}
```

Положите его в `<стенд>/gp/vnext/local/paths.json`. Каталог `vnext/local/` в `.gitignore` пакета —
в commit файл не попадёт.

- Файл **один на оба каталога инструментов копии**: его читают и `scripts/`, и `vnext/prototype/`.
  (До карточки #761 каждый каталог искал файл только рядом с собой, и второй файл нужен был в
  `<стенд>/gp/local/paths.json`. Это место читается по-прежнему и тоже закрыто в `.gitignore`.)
- Переменная `MEZO_CONTAINER` файл не заменяет: общий прогон приёмок по копии (`bite-all.py`)
  снимает её нарочно, чтобы испытуемые не ушли в живой контур.
- Нет файла — инструмент отказывает словами «контейнер группы НЕ НАЙДЕН» и называет, какой файл
  и с каким содержимым создать. Это отказ мерить, а не провал ветки.

## Шаг 4. Среда прогона

Нарочная поломка, расширяющая удаление или запись, идёт только в отдельной среде ВСЕГО дерева
процессов. Перед прогоном направьте шесть мест в короткий каталог РЯДОМ со стендом, а не внутри него
(например `<стенд>-t`): `TEMP`, `TMP`, `TMPDIR`, `HOME`, `USERPROFILE` и `MEZO_STAND_TEST_BIN`.
Ни в одном каталоге выше этой папки не должно быть `.mezosync/mezosync.db`: ни стенда, ни живого контура.

| переменная | значение | зачем |
|---|---|---|
| шесть мест выше | `<стенд>-t` — рядом со стендом, короткий путь | приёмки создают и удаляют каталоги во временной папке; живая временная папка и Корзина не трогаются. Внутри стенда нельзя: выше папки окажется база контура (см. «Ловушки») |
| `MEZO_STAND_MAX_AGE_H` | `0` | уборка стендов по сроку выключена: прогон не удаляет чужие каталоги |
| `MEZO_SCRIPTS_ROOT` | `<стенд>/gp/scripts` | какую копию инструментов испытываем |
| `MEZO_LIVE_DB` | `<стенд>/.mezosync/mezosync.db` | нужна отдельным приёмкам (см. «Ловушки») |
| `MEZO_CONTAINER` | снять (`unset MEZO_CONTAINER`) | одиночную приёмку запускают без `bite-all.py`, и переменную за неё никто не снимает, а `container_root()` читает её раньше всего остального: унаследованное значение может увести испытуемый инструмент в другой контур |

Приёмки гоняйте по одной, не параллельно.

## Шаг 5. Прогон

```bash
# одна приёмка
python -u <стенд>/gp/vnext/prototype/<имя приёмки>.py

# набор ядра: числа прогона против чисел списка core-bites.txt
python -u <стенд>/gp/vnext/prototype/bite-all.py --set core --target <стенд>/gp/scripts
```

- Запускайте из `<стенд>` (`cd <стенд>`): так вердикты двух рук сравнимы.
- Вывод читайте целиком и сохраняйте в файл: итоговая строка стоит в конце, а причина — где придётся.
- У приёмки с нарочными поломками вердикт двойной: случаи прошли И каждая поломка уронила ровно своё.
- Числа набора ядра сверяйте со списком `vnext/prototype/core-bites.txt`; «РАЗОШЛОСЬ» при том же
  расхождении на `main` — стенд, а не правка.

## Ловушки стенда — провал, причина которого не в ветке

| что видно | причина | что сделать |
|---|---|---|
| «контейнер группы НЕ НАЙДЕН», «корень мезосинка НЕ НАЙДЕН» | нет файла путей | шаг 3 |
| `bite-fresh-circuit.py` — числа меньше списка; `bite-update-tools-rev.py` — «не запустилась» | копия пакета — выгрузка `git archive`, истории нет | клон с историей, шаг 1 |
| `bite-update-tools-rev.py` — git: «Filename too long» | длинный путь временной папки (предел Windows — 260 знаков; замечено при каталоге длиннее ≈170) | короткий `TEMP`, шаг 4 |
| `bite-pack-copy-paths.py` — «⛔ ОПЫТ НЕ ПОСТАВЛЕН: стенд лежит внутри контура», код 2; набор ядра — «РАЗОШЛОСЬ» у `bite-drift-sanitize.py`, `bite-rules-from-pack.py`, `bite-two-locks.py` | временная папка лежит внутри стенда или другого контура: в каталоге выше неё есть `.mezosync/mezosync.db` | шесть мест шага 4 — в каталог рядом со стендом |
| `bite-target-selection.py` ⑧ ⑪, `bite-core-fixture.py` ⑰ — провал | пакет лежит не под контейнером | раскладка шага 2 |
| `bite-tool-brevity.py` ④ ⑫ — провал | в стенде нет `<стенд>/vnext-tools/check-dangling-refs.py` | каталог `vnext-tools` из шага 2 |
| `bite-temp-paths.py` ⑥ — «ДРУГАЯ проверка» | в стенде ЕСТЬ `<стенд>/vnext-tools`: случай сличает путь, а не текст | эту приёмку гнать на стенде без `vnext-tools` |
| `bite-open-fence.py` ③ ④-3 — провал | не передан `--scan-db` | `--scan-db <стенд>/.mezosync/mezosync.db` |
| `bite-memory-archive.py` — отказ кодом 2 | не названа база | `MEZO_LIVE_DB` из шага 4 |
| `bite-fresh-circuit.py` — «собрана с отказами» | в ветке есть файл, не добавленный в git: копия собирается только из файлов, известных git | это к автору — `git add` до прогона |

Две строки про `vnext-tools` противоречат друг другу: одной приёмке каталог нужен, другой мешает.
Пока это так, гоняйте их на двух раскладках и называйте раскладку в вердикте.

⛔ `bite-launcher-forms.py` не гоняйте на копии базы, в памяти ролей которой записаны пути
настоящего контура этой машины: проверка форм запускает программы по путям из памяти. Берите
свежий контур либо копию, где начало таких путей заменено каталогом стенда.
Это касается и общего прогона: `bite-all.py` без `--set` гонит все `bite-*.py` каталога, в том числе
эту, а `--only` отбирает по подстроке имени (`--only forms` её захватит). В наборе ядра (`--set core`) её нет.

Подменять пути можно только в КОПИИ базы и только в таблице `phoenix`, столбец `body`: проверка форм
берёт память ролей оттуда. Пути настоящего контура (`<контейнер>/…`) заменяются на `<стенд>/…`, все прочие
абсолютные пути (`C:/github/…`, `C:/Users/…`) — на `<стенд>/ext/…`: проверка форм запускает и их.
Подмена закончена, когда вне стенда не осталось ни одного абсолютного пути; повторный прогон ничего не меняет.
Рецепт ниже в пакет не входит: сохраните его файлом в стенде и запустите.

```bash
python <стенд>/memory-paths-to-stand.py <стенд>/.mezosync/mezosync.db <корень настоящего контура> <стенд>
# строк памяти N · изменено M · путей P · в стенде P · ВНЕ СТЕНДА 0   ← код 0; иначе код 1
```

```python
# Копия памяти ролей для bite-launcher-forms.py: пути настоящего контура → стенд, прочие абсолютные → <стенд>/ext.
# python memory-paths-to-stand.py <копия базы> <корень настоящего контура> <стенд>
# Повторный прогон ничего не меняет: путь, уже лежащий в стенде (и сам корень стенда), не трогается.
import re, sqlite3, sys
db, live, stand = (a.replace("\\", "/").rstrip("/") for a in sys.argv[1:4])
P = re.compile(r"(?i)(?<![A-Za-z])[A-Z]:[\\/][^\s`'\"<>|*?]+")
def in_stand(n):
    return n.lower() == stand.lower() or n.lower().startswith(stand.lower() + "/")
def fix(m):
    n = m.group(0).replace("\\", "/")
    if in_stand(n): return n
    if n.lower() == live.lower() or n.lower().startswith(live.lower() + "/"): return stand + n[len(live):]
    return stand + "/ext/" + n[3:]
con = sqlite3.connect(db)
rows = con.execute("SELECT rowid, body FROM phoenix").fetchall()
changed = 0
for rid, body in rows:
    new = P.sub(fix, body or "")
    if new != (body or ""):
        changed += 1
        con.execute("UPDATE phoenix SET body=? WHERE rowid=?", (new, rid))
con.commit()
paths = [p.replace("\\", "/") for (b,) in con.execute("SELECT body FROM phoenix") for p in P.findall(b or "")]
inside = [p for p in paths if in_stand(p)]
print(f"строк памяти {len(rows)} · изменено {changed} · путей {len(paths)} · в стенде {len(inside)} · ВНЕ СТЕНДА {len(paths) - len(inside)}")
sys.exit(0 if paths and len(inside) == len(paths) else 1)
```

Рецепт видит только пути вида `X:/…` и `X:\…` (Windows); пути вида `/home/…` он не находит.

## Чего приёмщик не делает

- не сливает, не устанавливает, не отправляет — вердикт не разрешение;
- не правит ветку автора: находка идёт комментарием, правит автор;
- не удаляет ничего вне своего стенда.

## Что написать в вердикте

```
кто и когда ......... <роль>, <дата и час UTC>
что принято ......... <ветка>, commit <вершина>
стенд ............... раскладка шага 2 (с vnext-tools или без), база — копия живой / свежий контур
прогоны ............. <приёмка>: код <N>, итоговая строка дословно
сверка с main ....... для каждого провала: тот же прогон на дереве без правки — код и строка
чего не проверено ... что не запускалось и почему
```
