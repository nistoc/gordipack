## Зачем этот выпуск

Шапка `read-phoenix.py --role <РОЛЬ>` выбирала блок «⛔ md ЗАМОРОЖЕНЫ» по одному наличию действующего правила
`md-to-sqlite-phased-cutover` и всегда печатала «ИСТОЧНИК ПРАВДЫ БД» и «при РАСХОЖДЕНИИ файла и БД — ВЕРЬ БД».
Фазу перехода, записанную в тексте правила, она не смотрела. Контур-потребитель на фазе 1 (двойная запись, md
главный, при расхождении верить md) получал в одном выводе состояние фазы 4 — противоположное своему — и вписал
обход в промпт подъёма каждой роли (замер контура-потребителя на пакете `1dcde23`, заявка issue #37).

## 3. Порядок для вашего контура

```
0 ... резервная копия — UPGRADE.md, раздел 3, шаг 0
1 ... план:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <вершина main>
      ожидаемо «≠» у read-phoenix.py и write-message.py и «+» у md-phase.py. «✋» — вы правили файл у себя:
      остановитесь и пришлите вывод
2 ... запись, второй план — до «+ ≠ ≈» нет:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <вершина main> --apply
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <вершина main>
3 ... шагов схемы нет — шаг 2 раздела 3 UPGRADE.md пропустите
4 ... фаза:
        python <КОНТУР>/.mezosync/scripts/md-phase.py
      «правило … в базе нет» — делать нечего, шапка прежняя; переходите к шагу 5.
      «правило … действует · признак … не записан» — фаза ваша, и её говорит текст правила, а не инструмент:
        python <КОНТУР>/.mezosync/scripts/set-rule.py --key md-to-sqlite-phased-cutover --show
      Кто вправе назвать фазу — тот, кто ведёт у вас переход (обычно владелец контура или координатор). Затем:
        python <КОНТУР>/.mezosync/scripts/md-phase.py --set <фаза> --actor <РОЛЬ> --dry-run
        python <КОНТУР>/.mezosync/scripts/md-phase.py --set <фаза> --actor <РОЛЬ>
      ожидаемо «✅ записано: meta.md_phase = <фаза> (было: —)» и строка «шапка read-phoenix.py печатает: …» —
      сверьте её с правилом
5 ... проба: python <КОНТУР>/.mezosync/scripts/read-phoenix.py --role <РОЛЬ> --full
      шапка говорит то же, что шаг 4: на фазе 1–2 — «ФАЗА N» и «ВЕРЬ md», на фазе 4 — «md ЗАМОРОЖЕНЫ» и «ВЕРЬ БД»
6 ... приёмка из клона; MEZO_CONTAINER=<КОНТУР> — испытуется <КОНТУР>/.mezosync/scripts:
        python <КЛОН>/vnext/prototype/bite-md-phase.py      ожидаемо «ИТОГ: 13 из 13» и код 0
```

⚠️ **Если контур обходил прежнюю шапку строкой в промпте подъёма ролей** («шапка печатает … — это НЕ наше
состояние»), после шага 5 эта строка лжёт уже в обратную сторону: шапка теперь говорит правду. Уберите её тем же
ходом — иначе роль получит два противоположных приказа, как до выпуска, только наоборот.
