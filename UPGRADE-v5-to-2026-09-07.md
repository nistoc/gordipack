## 2. Перед началом — два обязательных условия

1. Бэкап, проверенный **разворачиванием**: копия через SQLite backup API (файловая копия
   при живых писателях в WAL-режиме даёт рваный снимок), `SELECT * FROM schema_version`
   на копии обязан ответить `v5`, а `SELECT count(*) FROM schema_migrations` — числу
   шагов вашего журнала (у эталона перед этой серией — 25).
2. Сборка SQLite с FTS5: `python -c "import sqlite3;print(sqlite3.sqlite_version)"` и
   `SELECT sqlite_compileoption_used('ENABLE_FTS5')` → 1. Без FTS5 шаг поиска откажет
   словами, остальное накатывается.

## 3. Как обновиться

Инструменты — потребитель забирает пакет `scripts/` штатно:
```
python <КОНТУР>/.mezosync/scripts/update-tools.py            # план: что изменится
python <КОНТУР>/.mezosync/scripts/update-tools.py --apply    # запись; файлы со своей правкой — не трогает без --overwrite-unknown
```
Схема — 11 шагов и веха накатываются **в этом порядке** (порядок — по журналу эталона),
каждый сперва `--dry-run`, затем без него; каждый идемпотентен (повтор отвечает «уже
сведено»), обрыв лечится повтором:
```
migrations/20260830-backlog-reviewer.py
migrations/20260830-lease-waits.py
migrations/20260904-rule-skill-delivery.py
migrations/20260904-phoenix-archive.py
migrations/20260904-phoenix-records.py
migrations/20260904-phoenix-records-autoincrement.py
migrations/20260905-phoenix-history-archive.py
migrations/20260905-messages-archive.py
migrations/20260905-role-sessions.py
migrations/20260907-hint-seen.py
migrations/20260907-phoenix-records-fts.py
migrations/20260907-milestone-v6.py          # веха: ПОСЛЕДНЕЙ; сверяет НАБОР 11 шагов поимённо
```
⚠️ **Порядок — этот список, НЕ алфавит имён файлов** (замер 13.09 на свежем контуре): по
алфавиту `…phoenix-records-autoincrement` встаёт раньше `…phoenix-records`, которого требует,
а `…milestone-v6` — раньше `…phoenix-records-fts`. Цикл «по всем файлам каталога» ломается.
Веха отказывает, если под ней не хватает шага, и называет его по имени; при отказе —
прогнать недостающий шаг и повторить веху. После неё `SELECT * FROM schema_version`
отвечает `v6 · шагов N · сверх отметки 0`.
Автор шага берётся из окружения `MEZO_ROLE`; путь к базе — доводом `--db` (необязателен:
резолвится от расположения скрипта).

⚡ **С 2026-09-15 (карточка #633) свежий контур получает этот список АВТОМАТИЧЕСКИ** —
`init-group.py` накатывает его сам сразу после сборки базы, в том же порядке (канон —
`scripts/schema_step_order.py`, туда же дописан и шаг `20260915-foreign-rebirth-marks.py`,
см. следующую оговорку). Ручной прогон списка выше нужен только УЖЕ ЖИВОМУ контуру —
свежую сборку из этого документа он больше не касается.
⚠️ **Оговорка к шагу 20260905-phoenix-history-archive.py (карточка #640)**: 18 отметок
пересоздания, которые он сеет, — события контура-эталона; с 2026-09-15 шаг сеет их ТОЛЬКО
туда (различитель — `meta.group_name`). Контур, применивший шаг РАНЬШЕ этой даты, уже несёт
их под своими именами ролей — убрать (перенести, не удалить) поможет
`migrations/20260915-foreign-rebirth-marks.py`: сначала `--dry-run`, затем без него; проверка
результата — `SELECT role, at, source, noted_by, moved_at, moved_by, reason FROM
role_rebirths_foreign ORDER BY role, at;`.

После схемы:
- **Первый разбор записей** у каждой роли случится сам при её ближайшем сохранении памяти
  (строка «🧩 записи раздела: разобрано N записей (первый разбор)»); раньше — рукой:
  `python <ПУТЬ К ЗВЕНЬЯМ>/memory-records.py --role <РОЛЬ> --section <РАЗДЕЛ> --parse`
  (где лежат звенья образца у вашей раскладки — раздел 7.4).
- **Подсказки ролей** пересобрать генератором из свода (`rules-to-skills.py --write`) и
  прогнать проверку свежести — правка свода без пересборки оставляет роли старую редакцию
  (оплачено 07.09 16:01–16:36 UTC).
- **Реестр адресов**: каждая роль записывает свой адрес сама, КАЖДОЕ пробуждение, вместе
  с устойчивым номером сессии — форма и порядок в разделе 7.

## 6. Защита, встроенная из чужого промаха (30.08–07.09)
- Издатель пакета отказывается переносить файл, правленный в шаблоне после последнего
  переноса, и называет цену поимённо; перенос в образец отказывает на литерале пути этой
  машины в исполняемой строке — путь обязан вычисляться от расположения файла.

  а не в коде): «заморожено» значит «не править», а не «не звать».

## 7. Дополнение 2026-09-13: два шага после вехи v6 и пять починок

### 7.1 Схема — два шага ПОСЛЕ вехи v6
```
migrations/20260913-role-sessions-session-id.py   # устойчивый номер сессии роли + история перезаписей адреса

```
Приём тот же: `--dry-run`, затем без него; повтор отвечает «уже сведено». Новой вехи нет:
после них `schema_version` отвечает `v6 · шагов N · сверх отметки 2` — это ожидаемо.
Задним числом шаги ничего не заполняют: номер сессии знает только сама роль, а руку
старых отзывов не восстанавливают (подпись задним числом была бы правдоподобной, не настоящей).

### 7.3 Флаги `memory-records.py`: английское имя + прежнее русское как синоним
`--parse (--разобрать) · --rebuild (--пересобрать) · --show (--показать) · --select (--отобрать)
· --on-date (--за) · --revoked (--снятые) · --no-condition (--без-условия) · --full (--целиком)

Старые вызовы в памяти ролей продолжают работать; в новых текстах — английские.

### 7.4 Где лежат звенья образца (`vnext/prototype`) — AIA №4, №6, №12
Раскладок две, обе законные: у эталона звенья лежат в `<КОНТЕЙНЕР>/vnext-tools`, у контура,
собранного из пакета, — рядом со скриптами `<КОНТУР>/.mezosync/scripts`. `guard-all.py`,

### 7.6 Шаг пробуждения: адрес — КАЖДЫЙ раз, с номером сессии
```
1) номер своей сессии: вызов приложения get_session("self") → sessionId вида local_…
2) python <путь, который печатает промпт>/signal-templates.py --role <РОЛЬ> \
       --set-address "<имя [код]>" --session-id "<sessionId>" --source self
```
Имя с кодом в скобках меняется при возобновлении чата (13.09 у эталона сменилось у обеих
проснувшихся ролей); номер сессии — нет, и вызов приложения `send_message` его принимает.
Прямой сигнал соседнему чату несёт только указатель «записка #N в ленте», тело — лентой.

### 7.7 Ссылка «запись #N» в разделе прав памяти — AIA №9
`guard-rights-registry.py` засчитывает строку раздела прав, только если в ней ссылка
на строку реестра прав словом вплотную к номеру: «запись #N» или «право #N».
«записка #N» — номер ленты, не засчитывается. Запись обязана существовать, принадлежать
этой роли и не быть отозванной.
