## Зачем этот выпуск

Своя проверка общего прогона, своя настройка инструмента жили ПРАВКОЙ файла пакета. Такой файл каждое
обновление встаёт на «✋ ПРАВЛЕН У ТЕБЯ» и требует сведения (`--merge`) — ручной работы на каждом выпуске,
даже если в самом файле пакет ничего не менял. Теперь у своего есть свой каталог:

```
<каталог базы>/local/          ← .mezosync/local/: файл путей, перечень своих проверок, их скрипты
                                  обновление (update-tools.py) сюда НЕ пишет
```

а правленый файл, чья правка переехала в `local/` (или взята пакетом), отдаётся пакету одной командой —
`update-tools.py --release <файл>`: прежний текст уходит копией, на место встаёт версия пакета, и следующее
обновление идёт без «✋».

## 4. Поведение, которое изменилось

### 4.1 Каталог местного
`<каталог базы>/local/` — для живого контура это `.mezosync/local/`, где с выпуска 05.10 лежит файл путей
`paths.json`. Каталог идёт ЗА БАЗОЙ: прогон по копии базы видит `local/` своей копии. План и `--apply`
`update-tools.py` печатают одну строку:

```
🏠 местное ... <КОНТУР>/.mezosync/local: файлов 3 (checks/ · checks.json · paths.json) — обновление сюда не пишет
🏠 местное ... каталога нет (<КОНТУР>/.mezosync/local) — свои проверки и настройки кладут туда, обновление его не трогает
```

Ключ `prototype_install_dir`, указывающий ВНУТРЬ `local/`, не обслуживается (строка «⚠️ … туда обновление
не пишет, второй каталог не обслуживается»).

### 4.2 Свои проверки общего прогона — `local/checks.json`

```json
{"checks": [
  {"name": "чтение свода", "script": "checks/guard-rules-read.py", "args": ["--db", "{db}"]}
]}
```

- `script` — путь к скрипту; относительный считается от `local/` (скрипты кладут в `local/checks/`);
- `args` — необязателен; `{db}` заменяется путём базы, по которой идёт прогон (`--db` у `guard-all.py`);
  своего `--db` общий прогон местной проверке НЕ добавляет. Прочие относительные пути в `args` считаются от
  каталога, откуда звали `guard-all.py`, а не от `local/`;
- проверка — отдельный скрипт: код выхода 0 — прошла, иначе провал; вывод разбирается так же, как у
  проверок пакета.

Местные проверки идут ПОСЛЕДНИМИ, после всех проверок пакета, с приставкой «местная · »:

```
ℹ️ местных проверок: 1 — перечень <КОНТУР>/.mezosync/local/checks.json
```

`--skip` понимает имя и с приставкой, и без неё (`--skip "чтение свода"`). ⚠️ Имя местной проверки, совпавшее
с именем проверки пакета, `--skip` без приставки пропустит ВМЕСТЕ с ней — называйте свои по-своему. Провал
«местная · перечень» по `--skip` не пропускается нарочно: кривой перечень чинят, а не прячут. Провалом, а не тишиной, кончаются:
перечень не читается или не объект `{"checks": [...]}`; запись не объект; неизвестное поле (опечатка `arg`);
нет `name` или `script`; `args` — не список строк; одно имя дважды (всё это — «местная · перечень»); скрипта
по пути нет («скрипт местной проверки не найден: …»). Файла `checks.json` нет — норма: местных проверок нет
(строка «ℹ️ местных проверок нет» — только с `--full`; с выпуска 10.10 её знак — «🗂»: [`UPGRADE-2026-10-10-guard-skip.md`](UPGRADE-2026-10-10-guard-skip.md)).

### 4.3 `update-tools.py --release <файл>`
Только для файлов, которые план называет «✋ ПРАВЛЕН У ТЕБЯ» или «❓ … отпечатка установки нет». Имя — как в
плане (`guard-all.py`, `migrations/<имя>.py`); флаг можно повторять. Без `--apply` — только план:

```
   ⇄ guard-all.py   по --release отдаётся пакету: прежний текст — копией в <КОНТУР>/.mezosync/released/<дата-время UTC>/, на место — версия пакета
⇄ Отдаётся пакету по --release: 1 — правка из этих файлов должна жить в каталоге местного (…) или уже быть в пакете: перенесена ли она, инструмент проверить не может. …
```

С `--apply` прежний текст копируется в `<каталог базы>/released/<YYYYmmdd-HHMMSSZ>/` и СВЕРЯЕТСЯ побайтно до
того, как встанет хоть один файл пакета (не совпал — выход, файлы пакета не поставлены); затем на место
встаёт версия пакета и её отпечаток установки. Файл второго каталога установки (ключ `prototype_install_dir`)
копируется в `released/<…>/second-dir/<имя>`. Строки после записи:

```
⇄ отдано пакету по --release: 1 — guard-all.py
   прежний текст сохранён: <КОНТУР>/.mezosync/released/<дата-время UTC>
```

Имя, которое лежит и среди рабочих скриптов, и во втором каталоге установки, называют с каталогом:
`--release scripts/<имя>` или `--release vnext/prototype/<имя>`; голое имя в этом случае — отказ «назови, какой
отдать», ничего не тронуто.
Не отдаётся (строка «ℹ️ --release …», код 0): файл без своей правки («обновится и без --release»), файл,
равный пакету («уже равен пакету, отдавать нечего»). Отказ: файла нет среди инструментов пакета; `--release`
вместе с `--merge` / `--accept-merge` / `--record-only`.
⚠️ `--release` — не сведение: ваша правка в файл пакета НЕ переносится. Перенести её в `local/` (или
убедиться, что она уже в пакете) — ваша работа ДО `--release`; инструмент это проверить не может и говорит
об этом вслух.

### 4.4 Резервная копия уносит `local/`
`backup-db.py` после строки о файле путей печатает:

```
  📁 каталог местного <КОНТУР>/.mezosync/local (файлов N) попадёт в копию как <ЗЕРКАЛО>/local-copy/      (холостой прогон)
  📁 каталог местного скопирован: <ЗЕРКАЛО>/local-copy/ — файлов N                                        (--apply)
```

Файл, исчезнувший из `local/`, исчезает и из копии (строка «из копии убрано исчезнувших из local/: K»).
Убирается только то, что положил прошлый прогон: перечень положенного — `<ЗЕРКАЛО>/local-copy.list` рядом с
копией. Чужой файл в `local-copy/` не трогается и называется («в копии лежат файлы не из local/: …»). Кэш
байт-кода (`__pycache__`) не копируется. Копия НЕ трогается, если `local/` пуст, а прошлая копия нет (строка
«⚠️ … пуст, а в прошлой копии файлов N — копию НЕ трогаю»: пустой каталог чаще сбой; снять копию — рукой), и если
`local/` нет вовсе («каталога местного нет … — в копию не попал»). Выгрузку внутрь `local/` (`--out`) копия
не делает — легла бы в сам `local/`.
Восстановление: положить `<ЗЕРКАЛО>/local-copy/` как `<КОНТУР>/.mezosync/local/` (файл путей в нём тоже).
⚠️ Каталог зеркала — git-репозиторий: всё из `local/` попадает в его рабочее дерево. Паролей и ключей
в `local/` не держите.
