# Как обновить свой контур — с чего начать

> Входная страница для контура, собранного из этого пакета раньше и живущего своей жизнью.
> Отвечает на три вопроса: **на какой я версии · какой документ читать · в каком порядке
> обновляться**. Подробности каждого перехода — в документах `UPGRADE-*.md`, ссылки ниже.
> Все метки времени — UTC.

## 1. «Версия контура» — это три разные вещи

Инструменты, схема базы и свод правил обновляются РАЗНЫМИ командами и могут отставать
порознь. Смотрите все три — по одной команде на каждую:

| что | где записано у вас | как посмотреть |
|---|---|---|
| **инструменты** (`.mezosync/scripts`) | `meta.template_commit` — коммит пакета, из которого они взяты | `python <КОНТУР>/.mezosync/scripts/update-tools.py` без `--apply`: строка `версия ..... было <коммит> · стало <коммит>` |
| **схема базы** | журнал шагов `schema_migrations`, вид `schema_version` | `python <КОНТУР>/.mezosync/scripts/db-q.py "SELECT * FROM schema_version"` → например `v6 · 40 · 4`: отметка версии · шагов в журнале без вех · шагов после отметки |
| **свод правил** | таблица `rules` вашей базы против `rules/pack-rules.db` пакета | `python <КОНТУР>/.mezosync/scripts/rules-from-pack.py --summary` (инструмент приезжает с `update-tools.py`; нет его — сначала пункт 1 раздела 3) |

⚠️ `v6` — отметка версии СХЕМЫ, а не всего пакета. Между отметками пакет меняется много раз;
точная версия инструментов — коммит пакета. Обновляйтесь до НАЗВАННОГО коммита (`--rev <коммит>`),
а не до «что сейчас лежит последним»: тогда план, который вы прочли, совпадёт с тем, что ляжет.
Если `update-tools.py` отвечает «КОНТУР НЕ ЗНАЕТ СВОЕГО ИСТОЧНИКА» — контур собран до того, как
источник стали записывать: назовите его один раз `--source <путь к клону пакета или адрес>`.
Ответ «⛔ НЕ ЗАБРАЛОСЬ из локальный каталог … (не репозиторий)» — контур собран из ВЫГРУЗКИ пакета, а не
из клона: тот же ход, `--source <адрес пакета>` и при записи `--record-source` (проверено 2026-10-05,
документ выпуска 05.10, раздел 5).
Ответ «⛔ НЕ ЗАБРАЛОСЬ: версии <коммит> нет в <ПАПКА> (рабочая копия источника НЕ ТРОНУТА)» — источник
записан папкой клона пакета на вашем диске, а нового коммита в нём ещё нет: `update-tools.py` клон сам не
обновляет. `git -C <ПАПКА> fetch origin` — и тот же вызов заново; рабочую копию клона fetch не меняет.

## 2. Какой документ читать — по версии схемы

| `schema_version` у вас | что читать |
|---|---|
| `v1` | пути нет — он никогда не писался. Откройте заявку (раздел 5) |
| `v2` | [`UPGRADE-v2-to-v3.md`](UPGRADE-v2-to-v3.md) |
| `v3` | ⚠️ документа v3 → v4 нет. У эталонного контура между отметками v3 и v4 одиннадцать шагов, и три из них записаны в журнал под прежними именами (`008-…`, `009-…`), не совпадающими с именами файлов, — сверка по именам там не работает. Откройте заявку — допишем путь |
| `v4` | [`UPGRADE-v4-to-v5.md`](UPGRADE-v4-to-v5.md) |
| `v5` | [`UPGRADE-v5-to-2026-09-07.md`](UPGRADE-v5-to-2026-09-07.md) — разделы 3 и 7 подряд |
| `v6` | сверьте журнал с перечнем шагов (раздел 3, пункт 2), затем документы выпусков после отметки (раздел 4) |

Переходы идут ПО ОДНОМУ: с v4 до v6 — сначала весь документ v4 → v5 вместе с его вехой, потом
документ v5 → v6. Шаги следующей версии не накатывайте до вехи предыдущей: веха засчитает их
себе, и следующая веха откажет («сверх отметки ноль шагов»).

## 3. Порядок обновления — одинаковый для любого выпуска

```
0 ... резервная копия, проверенная разворачиванием:
        python <КОНТУР>/.mezosync/scripts/backup-db.py --apply
      куда легла — печатает сама; своё место — --out <ФАЙЛ> (файл, не папка).
      Копию она всякий раз проверяет разворачиванием
1 ... инструменты — план, затем запись:
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <коммит>
        python <КОНТУР>/.mezosync/scripts/update-tools.py --rev <коммит> --apply
      остались в плане «+» или «≠» — ещё раз --apply (первый прогон мог привезти новый
      update-tools.py, и только он знает, что ещё привезти);
      файл, который вы правили у себя, НЕ перезаписывается — план назовёт его; свести:
        update-tools.py --rev <коммит> --merge <ФАЙЛ>     черновик рядом, живой файл не тронут
        update-tools.py --accept-merge <ФАЙЛ> --apply     положить сведённое
2 ... схема — какие шаги у вас уже применены:
        python <КОНТУР>/.mezosync/scripts/db-q.py "SELECT version FROM schema_migrations ORDER BY rowid"
      сравните с перечнем STEPS в <КОНТУР>/.mezosync/scripts/schema_step_order.py
      (веха записана в журнал своим именем: шаг 20260907-milestone-v6 — строкой «v6»);
      каждый недостающий — В ПОРЯДКЕ ПЕРЕЧНЯ, не по алфавиту файлов, сперва холостым прогоном:
        python <КОНТУР>/.mezosync/scripts/migrations/<шаг>.py --dry-run
        python <КОНТУР>/.mezosync/scripts/migrations/<шаг>.py
      автор шага в журнале — из переменной окружения MEZO_ROLE (имя вашей роли)
      шаги из перечня NOT_SCHEMA_STEPS того же файла схему не меняют и в журнал не пишут:
      их зовут рукой так, как велит документ выпуска (у них холостой прогон — по умолчанию)
3 ... общий прогон проверок:
        python <КОНТУР>/.mezosync/scripts/guard-all.py
4 ... свод правил — список расхождений с пакетом:
        python <КОНТУР>/.mezosync/scripts/rules-from-pack.py
      впервые и много строк «опоры нет»? Сначала запишите опору там, где текст уже совпадает:
        rules-from-pack.py --record-base --actor <ваша роль> --apply
      дальше по каждому ключу: --show <ключ> — показать текст; ход — по состоянию строки:
        новое / изменено в пакете ...... --adopt <ключи> --word "<кто разрешил · когда · где>"
                                          --actor <ваша роль> --apply
        уточнено у вас / с обеих сторон ... --merge <ключ> --file <сведённый текст>
                                          --word "..." --actor <ваша роль> --apply
        не берём ....................... --skip <ключ> --word "..." --apply
      приложения к правилам, чей текст у вас уже совпадает с пакетом:
        rules-from-pack.py --annexes --actor <ваша роль> --apply
5 ... подсказки ролей — пересобрать из свода, иначе роли читают прежнюю редакцию:
        python <КОНТУР>/.mezosync/scripts/rules-to-skills.py --write
      (с коммита d32e621, 2026-09-14, его привозит сам update-tools.py — его зовёт шаг схемы
       20260904-rule-skill-delivery; у контура-эталона он лежит в vnext-tools)
```

Обрыв на любом шаге схемы лечится повтором: применённый шаг отвечает «уже сведено» (веха —
«уже объявлена») и журнал не растёт. Правила вы берёте по одному и со словом вашего владельца —
пакет ничего не навязывает. Отказ (`--skip`) запоминается по тексту пакета: ключ больше не
просит решения, пока пакет не изменит его текст.

## 5. Если не сходится

Заявка — в репозитории пакета: https://github.com/nistoc/gordipack/issues. Приложите три
строки раздела 1 (коммит инструментов, `schema_version`, итог сверки правил) и полный вывод
команды, на которой встали, — не пересказ: отказ инструмента называет причину своими словами.
