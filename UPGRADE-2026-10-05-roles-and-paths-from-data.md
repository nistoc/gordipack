## Зачем этот выпуск

Инструменты пакета несли имена и раскладку контура, из которого пакет вырос: роль `COORD` как
координатор по умолчанию, руку `COORD` у правок свода правил и реестра (у переноса ленты в архив — `PROTO`), каталоги `atlas.archs/…`, папку копии
базы эталона. В другом контуре такое умолчание либо молча писало не туда, либо приписывало правку роли,
которой у вас может не быть. Теперь:

- **кто координатор** — пометка в таблице ролей ВАШЕЙ базы (раздел 3);
- **где лежат каталоги контура** — файл путей `.mezosync/local/paths.json` (раздел 2);
- **чего нет ни там, ни там** — инструмент говорит это словами, а не подставляет чужое имя.

## 2. Файл путей

### 2.1 Шаг переноса

```
python <КОНТУР>/.mezosync/scripts/migrations/20261005-local-paths-file.py            # холостой прогон
python <КОНТУР>/.mezosync/scripts/migrations/20261005-local-paths-file.py --apply    # записать файл
```

⚠️ **Этот шаг устроен НЕ так, как шаги схемы** из `UPGRADE.md` (раздел 3, пункт 2):
- без флагов он НИЧЕГО не пишет (холостой прогон по умолчанию); запись — `--apply`, а не запуск без `--dry-run`;
- схему базы он не меняет, в журнал схемы (`schema_migrations`) не пишет и в перечне `STEPS`
  (`scripts/schema_step_order.py`) его нет — он назван там же в новом перечне `NOT_SCHEMA_STEPS`
  («шаги без изменения схемы»): сборка нового контура его не применяет и отставшим не считает,
  сверка журнала с перечнем о нём промолчит. База открывается только на чтение.

Что пишет: JSON-объект «ключ → путь» (относительный путь считается от контейнера контура) из того, что
контур хранил раньше — три ключа таблицы `meta` и строки `container=`/`template=` файла `local.paths`
рядом с инструментами. Пять каталогов прежней раскладки эталона (`coordination_dir`, `generated_dir`,
`prompts_dir`, `spa_src`, `annex_dir`) вписываются, только если такой каталог ЕСТЬ на вашем диске; у
контура без них ключи не вписываются, и инструменты берут стандартную раскладку пакета (таблица 2.2).
Повторный прогон отвечает «уже перенесено» и файл не переписывает — вашу дописку рукой не тронет.

Контур, собранный из пакета и не хранивший путей ни в `meta`, ни в `local.paths`, получает ответ
«✅ нечего переносить … Файл не создаю — инструменты читают стандартную раскладку пакета» — это норма,
файл путей такому контуру не нужен. Строки над ним «прежняя раскладка автора (контур Atlas): …
каталога … на диске нет — ключ не вписываю» — справка о каталогах эталона, а не ошибка.
Прежние источники шаг НЕ удаляет: печатает, что они больше не читаются. Ключ `meta.template_source`
(адрес пакета) остаётся в `meta` и читается как раньше.

Между `update-tools.py --apply` и этим шагом инструменты, читающие перенесённые ключи, отвечают
«не объявлено» и печатают готовую команду шага — поэтому шаг идёт сразу за обновлением инструментов.

### 2.2 Ключи файла путей

Свой каталог, которого шаг не знает, впишите в файл рукой (JSON, путь абсолютный или от контейнера).

| ключ | кто читает | если ключа нет |
|---|---|---|
| `container` | поиск контура, когда копия инструментов лежит вне контейнера | ключ читается ПОСЛЕ среды `MEZO_CONTAINER` и поиска базы вверх по каталогам; не нашлось ничего — отказ с подсказкой |
| `template` | поиск образца пакета | ключ читается ПОСЛЕ среды `MEZO_TEMPLATE` и поиска `scripts/init-group.py` вверх по каталогам; не нашлось ничего — отказ с подсказкой |
| `mirror_repo` | `backup-db.py`, `guard-scripts-drift.py` | копия базы ложится в `<каталог базы>/backups`; сверка с зеркалом печатает «не объявлено», код 0 |
| `template_checkout` | `rules-from-pack.py`, `guard-scripts-drift.py` | правила пакета берутся временным clone по `meta.template_source`; образец не сверяется, текст называет ключ |
| `disk_layer_tool` | `read-phoenix.py` | слой памяти на диске не собирается, это сказано словами |
| `coordination_dir` | `write-message.py`, `export-rules.py`, `check-rules-mirror.py` | каналы — `<контейнер>/coordination`; файл правил — `.mezosync/generated/sync.rules.md`; зеркало правил не сверяется |
| `generated_dir` | `export-channels.py`, `guard-printed-forms.py` | `.mezosync/generated` |
| `prompts_dir` | `guard-command-targets.py` | `.mezosync/templates`, если есть; иначе промпты не сверяются — свойство контура, не долг |
| `spa_src` | `guard-stub-expectations.py` | не сверяется — свойство контура, не долг |
| `annex_dir` | `set-rule.py --annex`, `rules-from-pack.py --annexes` | `.mezosync/rules-annex` |

**файла нет** · **не читается** (битый JSON, верх не объект). Пишущий инструмент на «не читается»
останавливается словами, а не пишет в стандартное место.

## 3. Координатор контура

```
python <КОНТУР>/.mezosync/scripts/role-rights.py coordinator
```

Пометка — слово «координатор» в причине (`roles.lifecycle_reason`) РОВНО ОДНОЙ живой роли, без
оглядки на регистр. Три разных ответа: одна роль — названа по имени · никого — «не назначен» ·
несколько — «не определён» с именами всех найденных.

Помечена не ровно одна роль — назначить по живому слову владельца вашего контура:

```
python <КОНТУР>/.mezosync/scripts/role-rights.py coordinator --set <РОЛЬ> --actor <РУКА> --word "<слово владельца дословно, час UTC, чат>"
python <КОНТУР>/.mezosync/scripts/role-rights.py coordinator --set <РОЛЬ> --actor <РУКА> --word "<…>" --apply
```

Без `--apply` печатает, что изменится, и ничего не пишет. С `--apply` одной транзакцией: роль получает
пометку (прежний текст причины остаётся после неё), у всех прочих помеченных пометка снимается текстом
«прежняя ведущая роль контура; пометка снята <час> UTC», след уходит в журнал изменений (`audit_log`,
действие `set_coordinator`); если после записи поиск не возвращает назначенную роль — всё откатывается.
⚠️ Подлинность слова владельца инструмент НЕ проверяет — записывает, как названо.
⚠️ Не пишите рукой «бывший координатор»: поиск идёт по корню слова и такую роль тоже посчитает
координатором. Команда выше пишет текст без этого корня.
⚠️ Роль должна уже быть в таблице ролей и быть живой — иначе отказ. Контур, собранный до 26.09 с
пустым реестром, сначала заводит роль строкой из раздела 5 прежнего документа.

Кто берёт координатора из данных: `set-rule.py` и `set-registry.py` (рука, когда она не названа) ·
`role-rights.py revoke --foreign` · `gordi-issue.py` (писатель канала заявок) · `rules-from-pack.py
--propose` и `backlog.py` (готовые команды в подсказках) · `dashboard.py` (первая карточка) ·
`guard-printed-forms.py` (чью память читать, когда роль не названа) · `role-brief.py`.

## 4. Поведение, которое изменилось

### 4.1 Рука правки свода и реестра
`set-rule.py` и `set-registry.py` ищут руку по порядку: `--actor` → среда `MEZO_ROLE` → координатор из
данных (одна строка «пишет: <РОЛЬ> (координатор контура; --actor не дан)») → отказ словами. Чтение
(`--list`, `--show`, `--annex`, `list`) и холостой прогон руки не требуют. У `set-registry.py` снято
умолчание «coord» у «кто установил» — им становится рука. Касается хуков и скриптов, зовущих эти
инструменты с `--apply` без `--actor`: при помеченном координаторе запись пойдёт от него, без пометки —
отказ.

### 4.2 Сборка нового контура
`init-group.py --roles <РОЛЬ> [<РОЛЬ> …]` — роли называет вызов; без `--roles` отказ с примером, база не
создаётся. `--coordinator <РОЛЬ>` — кого пометить координатором (по умолчанию первую из `--roles`); роль
вне `--roles` — отказ. Раскладка эталона: `--roles coord core …` даёт координатора `COORD`, как прежде.
Шаги из перечня `NOT_SCHEMA_STEPS` сборка не применяет и печатает их строкой «ℹ️ Шаги без изменения
схемы сборкой не применяются»; у нового контура переносить нечего — файл путей он заводит рукой,
если нужен.

### 4.3 Резервная копия
`backup-db.py --apply` кладёт рядом с выгрузкой копию файла путей под именем `local-paths.json`; файла
нет — строка «в копию не попал», выгрузка всё равно записана. Разворачивая копию, положите
`local-paths.json` обратно в `.mezosync/local/paths.json` — об этом же говорят шапка выгрузки и справка.

### 4.4 Волна A (`8eaa287`)
Одна общая функция `find_coordinator` в `mezo_paths.py` вместо трёх копий правила отбора;
`gordi-issue.py`, `role-brief.py`, `rules-from-pack.py` переведены на неё. Справка `backlog.py` — у всех
девяти подкоманд, без номеров карточек; у флагов одного смысла приняты вторые имена.

### 4.5 Заявка пакета №36 (контур AIA), случай ⑰б
С `7d55cb9` приёмка `bite-rules-from-pack.py` не зовёт `gordi-issue.py create` с писателем `COORD`: на копии
базы она сама назначает пробного координатора `ZZK` и сверяет, что назван ровно он. Прежде на контуре, где
координатор назван иначе (у AIA — `COORD-A`), случай ⑰б и поломка (С) падали отказом «не координатор»
раньше, чем доходило до разбора тела письма.

### 4.6 Файл без отпечатка установки, равный версии пакета (`94b45b3`)
Отпечатки установки (`meta.template_files_sha`) пишутся не с первого выпуска; у файла, поставленного раньше,
его нет. Прежде такой файл всегда шёл в «❓», и взять его можно было только `--overwrite-unknown` — флагом,
который действует на ВСЕ файлы разряда сразу. Теперь `update-tools.py` ищет текст такого файла в истории
пакета: нашёл — это старая версия пакета без вашей правки, строка плана
«≠ <файл> отличается — обновится: отпечатка установки нет, текст — версия пакета от <дата> (коммит …) … —
своей правки нет», и `--apply` берёт его и пишет отпечаток. Найдено контуром AIA 2026-10-05 на
`guard-printed-forms.py`. Ищет НОВАЯ `update-tools.py`, а план строит та, что стоит у вас: версия старше
`94b45b3` ещё печатает такой файл строкой «❓ … — версия пакета от <дата> (коммит …)». Первый `--apply`
привозит новую `update-tools.py`, повторный план показывает файл строкой «≠», второй `--apply` его берёт
(раздел 5, шаг 1). Граница: файл, который вы НАРОЧНО вернули к старой версии пакета, без отпечатка
от нетронутого не отличить — он обновится; с отпечатком он виден как «✋», и этот путь не менялся.

```
      строка «версия ..... было версия неизвестна · стало …» у такого контура — норма
      ответ «⛔ НЕ ЗАБРАЛОСЬ: версии 94b45b3 нет в <ПАПКА> (рабочая копия источника НЕ ТРОНУТА)» значит:
      источник записан папкой клона пакета на вашем диске, а нового коммита в клоне ещё нет —
      update-tools.py клон сам не обновляет. Заберите историю и повторите шаг 1:
        git -C <ПАПКА из этой строки> fetch origin
      fetch не меняет рабочую копию клона: ваши правки в нём и его текущий коммит остаются как были
      план назвал файл, который вы правили у себя, — он не перезаписывается; это остановка (⛔ в начале
      документа). Сведение --merge <ФАЙЛ> / --accept-merge <ФАЙЛ> --apply (UPGRADE.md, раздел 3) — только
      по слову вашего владельца
      строка «≠ … отпечатка установки нет, текст — версия пакета от … — своей правки нет» — НЕ остановка:
      файл старой версии пакета, --apply его берёт (раздел 4.6)
      строка «❓ … отпечатка установки нет — версия пакета от <дата> (коммит …)» — тоже НЕ остановка: так
      печатает update-tools.py старше 94b45b3 файл, текст которого найден в истории пакета. --apply заберёт
      новую update-tools.py и все «≠», файлы «❓» не тронет; повторите план — тот же файл придёт строкой
      «≠ … своей правки нет», и ещё раз --apply (раздел 4.6). Если «❓» стоит у самой update-tools.py,
      повторный план ничего не изменит — это остановка
      строка «❓ … отпечатка установки нет» БЕЗ версии пакета («в истории пакета такого содержимого нет»
      или «истории у источника нет») — остановка: своей ли правкой файл отличается, инструменту не доказать.
      Флаг --overwrite-unknown возьмёт версию пакета у ВСЕХ файлов «❓» сразу и затрёт в них свои
      правки — только по слову вашего владельца, назвав ему каждый файл «❓» из плана
1b .. схема: в этом выпуске шагов схемы нет. Сверка журнала с перечнем STEPS (UPGRADE.md, раздел 3, пункт 2)
      должна показать, что недостающих нет; есть недостающие — контур старше выпусков раздела 4 UPGRADE.md,
      сначала их документы
2 ... файл путей — холостой прогон, прочитать, затем запись (раздел 2):
        python <КОНТУР>/.mezosync/scripts/migrations/20261005-local-paths-file.py
        python <КОНТУР>/.mezosync/scripts/migrations/20261005-local-paths-file.py --apply
      свои каталоги, которых шаг не знает, — вписать в .mezosync/local/paths.json рукой
3 ... координатор — посмотреть; не ровно одна роль — назначить по слову владельца (раздел 3):
        python <КОНТУР>/.mezosync/scripts/role-rights.py coordinator
4 ... свои хуки и скрипты: --apply у set-rule.py, set-registry.py, messages-fold.py без --actor/--role
      и без MEZO_ROLE — дописать флаг (раздел 4.1). set-rule.py и set-registry.py без флага пишут
      от помеченного координатора; messages-fold.py без флага отказывает
5 ... общий прогон проверок:
        python <КОНТУР>/.mezosync/scripts/guard-all.py
```
